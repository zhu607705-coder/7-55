# 昌平柳湖主池：独立原画水面

基于 Draft #133 精确提交 `bca86c2b10901c0c524968e4b79f2b45845cf729`，树 `8f135d0c44e0efc56a6e81522f644fcb00e4f67e`。

## 可体验内容

柳湖主池从原画中分离为一个固定地理位置的 `LiuLakeMainSurface` 节点。它只有一个独立水面 Sprite2D。默认保留原水色，并加入很轻的低速微动。点击真实水像素可选择水面；点岛、岸或其他空白处可取消。状态文字沿用原游戏样式。

没有新增 POI、导览点、岸边路线或水中通行。原南门出生点、41 个路点、3 个 POI、图书馆/第一教学楼/东路和共享学生保持原合同。水对象不能搬走整湖。

本轮不含南桥下窄渠或南段荷塘，也不修改室内、正式 TileMap 或浙大主线。

## 像素来源与透明边界

- 仍用已批准的 `approved-changping.png`，950 × 1656；原大 PNG 的字节没有变
- 源 SHA256：`f92a8de6ef703bab4b2e471a49acc082dd4d128d264d99d3ed1818fdb0c93707`
- 固定裁框 `[317,750,163,108]`，真实非透明水像素 7,140 个
- 新文件只有 163 × 108 的原水 RGBA 和同尺寸岸缘距离纹理；不是重画湖、生成新的水形或整幅图替换
- RGBA 所有非透明 RGB 与原画相同；真实透明 alpha 排除陆地、岛上树、北端深色构筑物/投影、北岸平台、东岸枝叶与南桥
- 原图在岛西南有可见陆地/树冠连接。因此透明排除区与外岸相连，拓扑上没有封闭孔洞。不会补画不存在的环岛水道

遮罩使用人工限定 ROI、水色连通域、封闭水中亮反射恢复和人工干燥对象排除，再向内退 1 源像素。亮反射恢复涉及 82 像素；最后的保守岸缘退让保留 729 个混合边缘像素在静态层。具体阈值、种子、排除多边形和 SHA 记录在 `data/liuhu_water_registration.json`。这是对艺术图的保守分层，不是测绘级岸线。

校区参考来源：北区办校园图页面 https://bq.buct.edu.cn/233/listm.htm 。所用官方图为页面提供的 2023 年 6 月版本，将图书馆西侧主池标为柳湖；并非声称 2026 年测绘。

## 图层与原子安装

原底图只增加一个使用同一 alpha 的互补裁空 shader。大纹理仍共享，不复制整幅图。水层与静态岸/岛层逐像素互补，隐藏水节点时真实露空，不保留一份假独立的底图水，不生成湖床。

安装顺序是检查原底图所有权 → 加载正式导入纹理 → 验证尺寸、非 mipmap 与解码像素 SHA → 完整构建水节点 → 最后安装互补材质。缺水/距离纹理或同尺寸错误像素会失败，原底图不先被挖空。运行时不依赖只在源码工作区才存在的 raw PNG 读取。

## 微动约束

- alpha、岸线、图层位置与源坐标不随时间变化
- 距 alpha 边缘 2 源像素内完全静止，其内用 8 源像素权重渐变
- 最大横向偏移 0.30 源像素，角速度参数 0.65 rad/s
- 四个 RGB 插值样点都必须属于水 alpha，否则回退原像素
- 无海浪、发光、岸线呼吸或桥树一起抖动
- `set_animation_enabled(false)` 原位回到原水采样。三次关闭/恢复不累积位移

## 行走与选择

水面与现有铺装零重叠。最近铺装距所选水像素约 87.05 源像素，现有合法路线上的 18 像素共享学生不能触到湖岸树冠。本轮不虚构新的岸树脚深度或树干碰撞。

原鼠标/触屏统一走 `_pointer_pressed`，只有 `is_walkable(target)` 为真才寻路。本补丁保留这一条件。水点击只做独立 alpha 选择；岛和透明区不命中水。选择是幂等的，避免触屏伴生鼠标事件造成重复切换。取消选择会恢复原步道提示，不残留“柳湖”选中文字。

## 已验证

- Node 源检查：89/89；含冻结资源哈希、两个新资产、原像素 RGB、alpha 样点和固定采样边界合同
- 原生水组件：最终 59/59；覆盖 7,140 个水像素全部禁行、完整裁框 alpha 命中、资源原子失败、共享学生与原建筑、三次动画开关、鼠标/触屏选中与取消、取消文字
- 原东路原生回归：41/41；连续出生点→东路 A/B→出生点、原导览、既有碰撞和按键边界均保留
- 实际 GPU 捕获：15/15；1180 × 812 实际窗口。原导览 718 个物理帧，非法脚点 0，仍只探访原 3 个 POI，没有在连续导览途中写入人物坐标
- GPU 严格像素分析：18/18。静态合成与三次关闭动画的全窗差异均为 0 像素。隐藏水层恰好移除 114,240 屏幕水像素，水外变化 0
- 4 个动态波相水外变化 0、固定岸缘变化 0，最大通道变化分别为 3、8、9、7（8 位通道）
- 最终人工 GUI：真实点水→岛/空白取消→重新选中，文字正确，仍为 3/3 POI；S 键短按仍沿原路径移动且松开停下。选中与取消时人物不动为目视检查，不冒充逐输入坐标计数
- 105 张实际 GPU 帧，15 fps，构成 7 秒局部微动证据。局部是原比例 792 × 532 裁切，不插帧、不拉伸，已编码 H.264/CRF16、66,755 字节，ffprobe 确认 105 帧/7.000 秒；正常游戏画面另行保留完整实际窗口

GPU 捕获后仅补了取消水选择时恢复状态文字的 UI 尾修，没有改水材质、纹理、几何或正常游戏相机；最终 59 项测试覆盖该尾修。此外仅将未参与渲染的来源字段规范为仓库路径。详细结果见 `BUCT_CHANGPING_LIUHU_VALIDATION.json`。

## 保留的失败与边界

1. 初次原生启动：最小测试 stage 缺少从 `src` 镜像的共享字体；此外 JSON 数字是 float，不能用 `Array[int]` 字面量直接比较。已补精确字体 blob 校验，并用数值 Vector4 比较
2. Headless 的默认 64 × 64 dummy 窗口不适合输入测试，现由该测试显式设 1440 × 900 逻辑窗口。实际 GPU 仍记录真实 1180 × 812，不能混称为测试请求尺寸
3. 初版“点水切换选择”会受触屏伴生鼠标事件双触发影响。改为点水幂等选中，点透明区域取消；不改变原输入或寻路处理
4. 首次 GPU wrapper 在 Godot 15/15 完成后因宿主只有 `python3` 而无 `python`，分析命令返回 127。保留原 127，修改 wrapper 后单独执行分析得到 exit 0 与 18/18；没有把原 wrapper 改记成成功，也没有为此重录
5. 本测试新增证据输出为可选：未设 `BUCT_LIUHU_OUTPUT` 不写文件；显式无效位置清楚失败，不调用空文件对象或写根目录
6. 这是一处可辨主池的保守分层；混合岸缘仍静态。没有宣称全校水系均已拆分，也没有开放现实或游戏湖岸通行

## 复现

先按原项目流程完成正式资源导入，再在仓库根目录运行：

```sh
node scripts/check-buct-changping-liuhu.mjs
bash scripts/test-buct-changping-liuhu.sh "$PWD/godot_native" headless
bash scripts/test-buct-changping-liuhu.sh "$PWD/godot_native" proof
```

源检查与 native test 已接入既有 `godot_native/tools/test_buct.mjs`。新 test 在顶层扫描器不提供可选证据环境变量时也能独立运行。`proof` 需要已有显示环境；脚本不启动 X server。所有临时目录均在当前工作区，不并行启动 Godot 实例。

正常游戏截图和 7 秒局部视频单独交付，不放入运行时资产。
