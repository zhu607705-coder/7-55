# 第四章楼梯间三视角空间解谜详细设计

> 2026-08-09 状态：该文档保留为已完成的独立 Three.js 原型设计记录。Godot 迁移内容已失效；原型不进入当前教学楼主线，主线先完成纯俯视大地图验收。

## 1. 文档目的

本文件定义第四章两个独立楼梯间关卡的玩法、投影连通、点击移动、像素美术、转场、输入、状态和验收标准。目标是把当前仅依赖机关数值的 Three.js 原型升级为真正利用正交投影形成临时通路的空间解谜，同时保持与启真湖过场、段永平教学楼门厅和现有 RPG 人物一致的硬边像素画面。

本阶段只处理独立入口 `chapter4-monument-stair-demo.html`。正式章节接入和 `GameState` 写入已暂停；主 `demo/index.html` 当前只接入纯 Phaser 教学楼地图。

## 2. 当前问题

现有原型已经具备两关、正交相机、机关选择、点击移动和断路停边，但仍有四项结构性缺口：

1. 通路由 `mechanism.value === requiredValue` 判定，视角没有参与连通结果。
2. 相机只有一个主视角和轻微指针偏移，玩家无法通过切换观察方向制造视错觉通路。
3. 场景原先使用没有像素采样约束的 PBR 材质、抗锯齿、柔和阴影、雾和圆角玻璃 UI，与前后章节的 `480×270 → 960×540` 最近邻像素画面不一致。
4. 人物由三维胶囊和球体组成，动作、比例、脚底锚点与共享 RPG 人物资产不一致。

## 3. 设计目标与范围边界

### 3.1 必须达到

- 两个关卡都使用三个离散正交视角，视角切换实际改变可走图。
- 至少三件机关共同参与第一关，四件机关共同参与第二关。
- 第一关包含一次投影连通；第二关包含两次投影连通和一次可理解的错误重合。
- 点击可到达目标时走到目标；目标不可达时走到当前连通分量的最近边缘后停下。
- 人物行走投影边时保持连续，途中禁止切换视角和操作机关。
- 画面以 `480×270` 内部像素网格渲染，再最近邻放大到 `960×540`。
- 桌面、触屏、减弱动态模式均能完成两关。

### 3.2 本阶段不做

- 不增加自由旋转镜头。
- 不加入物理坠落、跳跃、战斗和倒计时。
- 不接入正式章节存档、任务、钱包、道具或当前 Phaser 主线。
- 不修改已删除的校园主地图资产，也不借此解除主单文件构建阻断。
- 不新增自动化测试依赖；通过确定性调试接口、构建验证和真实浏览器流程验收。

## 4. 方案选择

采用“三个离散正交视角 + 投影端点图”。每个可走表面输出端点、切线、所属平台和允许视角。相机完成切换后，把端点投影到内部 `480×270` 屏幕坐标，按照距离、方向、遮挡和关卡白名单生成临时边。

### 4.1 备选方案

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 自由轨道相机 | 观察自由度高 | 触屏控制复杂，容易产生偶然连通，关卡难以稳定验收 | 不采用 |
| 固定单视角、机关数值开门 | 实现简单 | 无法体现视角参与，保留了当前原型的主要问题 | 不采用 |
| 三个离散正交视角、投影图重算 | 视错觉可控，移动端清晰，关卡可重复验收 | 需要精确处理端点、遮挡和移动锁 | 采用 |

## 5. 核心系统设计

### 5.1 视角状态

每关固定三个视角，按钮只显示方向字形和当前序号，键盘等价键为 `1 / 2 / 3`。

| ID | 显示名 | 参考相机位置 | 主要用途 |
| --- | --- | --- | --- |
| `south_east` | 东南 | `(12, 11, 14)` | 阅读入口、低层平台和横移机关 |
| `south_west` | 西南 | `(-12, 11, 14)` | 形成第一类横向投影重合 |
| `top_oblique` | 上方 | `(0, 17, 12)` | 阅读高层、升降高度和第二类投影重合 |

- 三个相机均为 `OrthographicCamera`，使用同一 `lookAt` 中心和同一可见范围。
- 禁止指针驱动的镜头漂移，保证同一状态每次得到相同投影。
- 视角切换时长为 `480ms`；切换期间暂停移动、机关、点击和再次切换。
- 玩家在任意节点站定后均可切换视角，包含楼梯端点和机关台面；人物行走、投影边通行、机关动画或相机转场期间，视角按钮保持可见并呈禁用状态。第二关的连续上行接缝使用不同视角，避免同一视角贯穿整关。
- 减弱动态模式将切换时长降到 `1ms`，仍执行同一重算流程。

### 5.2 端点数据

每个楼梯、平台、升降台和出口暴露一个或多个连接端点：

```ts
interface PerspectiveConnector {
  id: string;
  ownerId: string;
  worldPosition: THREE.Vector3;
  worldTangent: THREE.Vector3;
  nodeId: string;
  views: CameraViewId[];
  linkGroup: string;
  projectionMode: "physical" | "perspective";
}
```

`linkGroup` 只允许作者明确配对的端点参与比较，防止场景中无关几何偶然重合。

### 5.3 投影连通规则

相机稳定后执行一次完整重算：

1. 使用 `Vector3.project(camera)` 把端点转换为内部 `480×270` 坐标。
2. 两端点必须属于同一 `linkGroup`，并允许当前视角。
3. 屏幕距离不超过 `6px`。
4. 两条投影切线夹角满足相向连接：归一化点积小于等于 `-cos(20°)`。
5. 从相机到端点的射线不能先命中不属于该端点的实心遮挡面。
6. 机关、相机和平台动画均已结束。

满足全部条件时生成 `perspective` 临时边，画面显示青色实线接缝。距离满足但方向失败时显示橙色虚线接缝，并且不写入导航图。

### 5.4 导航图与点击移动

导航图包含三类内容：

- 固定平台和楼梯内部的 `physical` 边。
- 当前机关状态产生的真实机械连接边。
- 当前视角产生的 `perspective` 临时边。

点击场景后执行以下流程：

1. 射线命中可走表面并得到最近导航节点。
2. 从玩家节点运行最短路搜索。
3. 目标可达时沿完整路径移动。
4. 目标不可达时，在玩家当前连通分量内选择屏幕方向最接近目标的边界节点，并移动到该节点。
5. 到达断点后只显示一次局部反馈：`通路在这里中断。调整机关或切换视角。`

有效投影边按白名单中的 `connectorA → connectorB` 声明上行方向。两端在屏幕上近乎重合时，方向键和移动端方向按钮不得使用亚像素差值猜测方向：`↑` 固定沿 `A → B` 跨越，`↓` 固定沿 `B → A` 返回。左右键继续按屏幕方向选择普通相邻节点。

投影边通行期间记录 `lockedPerspectiveEdgeId`。相机、机关和关卡重置均被锁定，直到人物脚底进入另一端安全节点。

### 5.5 机关交互

- 点击机关实体会选中它，选中框贴合机关实际包围盒。
- 选中后才显示两枚方向控制：旋转机关显示顺/逆时针，横移和升降机关显示对应轴向。
- 桌面使用 `Q / E`，触屏点击贴近机关的两个像素按钮。
- 机关每次只移动一个离散档位，时长 `420–520ms`。
- 机关运动期间人物保持在安全节点；若人物站在该机关上，机关可以携带人物，结束后统一更新脚底节点。
- 机关停止后先更新世界矩阵，再重算端点投影和导航图。

## 6. 第一关：折返楼梯间

### 6.1 教学目标

让玩家理解三件事：机关能改变真实位置；视角能改变临时连接；画面重合仍需满足行进方向。

### 6.2 机关与状态

| 机关 | 状态 | 初始 | 关键状态 | 作用 |
| --- | --- | --- | --- | --- |
| 入口横移台 | `0/1/2` | `0` | `1` | 把起点平台接到中央梯段下方 |
| 中央旋转梯 | `0/1/2/3` | `1` | `0` | 在西南视角将上端投影到中层孤台 |
| 出口升降台 | `0/1/2` | `0` | `1` | 在上方视角接住中层孤台并抬到出口 |

共 `36` 个机关组合。只有一条完整流程可以在不重置的情况下到达出口，但玩家可以随时回调已操作机关。

### 6.3 空间与节点

- `A_START`：入口安全平台。
- `A_SLIDE`：入口横移台。
- `A_STAIR_LOW` / `A_STAIR_HIGH`：中央梯段两端。
- `A_MID_ISLAND`：与真实楼梯相距较远的中层孤台。
- `A_LIFT`：出口升降台。
- `A_EXIT`：消防门前平台。

### 6.4 预期解题过程

1. 东南视角下把入口横移台调到中档，点击中央梯段下端，人物走到 `A_STAIR_LOW`。
2. 将中央梯段旋到关键朝向。此时真实空间仍有断口。
3. 切换西南视角；`A_STAIR_HIGH` 与 `A_MID_ISLAND` 投影重合，出现青色实线接缝。
4. 点击中层孤台，人物沿投影边通过。通过期间视角和机关锁定。
5. 切换上方视角，把出口升降台调到中档，孤台与升降台形成真实短接。
6. 点击消防门，人物到达 `A_EXIT`，完成第一关。

该流程不在任务栏中逐项展示。任务只显示：`让入口、中央梯段和出口在合适视角中连续。`

### 6.5 可读反馈

- 首次出现有效投影接缝时显示 `这个视角下，两端连在一起。`
- 玩家在错误视角点击孤台时走到楼梯上端并停下。
- 升降台高度错误时，出口门保持正常亮度，台面边缘出现一条短橙线。
- 完成后相机保持当前视角，消防门打开四帧，人物走入门内，再进入第二关过场。

## 7. 第二关：环形错层楼梯井

### 7.1 教学目标

要求玩家连续维护两次投影关系，并识别“位置重合、方向不通”的错误连接。

### 7.2 机关与状态

| 机关 | 状态 | 初始 | 关键状态 | 作用 |
| --- | --- | --- | --- | --- |
| 下层旋转梯 | `0/1/2/3` | `1` | `3` | 在西南视角连接起点与中层升降台 |
| 中层升降台 | `0/1/2` | `0` | `2` | 把人物送到上层旋转梯下端 |
| 上层旋转梯 | `0/1/2/3` | `0` | `1` | 在上方视角连接高层孤台 |
| 出口横移台 | `0/1/2` | `0` | `2` | 将高层孤台接到最终消防门 |

共 `144` 个机关组合。两个投影连接分别属于 `B_LOWER_LINK` 和 `B_UPPER_LINK`，不能跨组误连。

### 7.3 空间与节点

- `B_START`：下层入口平台。
- `B_LOWER_LOW` / `B_LOWER_HIGH`：下层旋转梯。
- `B_MID_LIFT_LOW` / `B_MID_LIFT_HIGH`：中层升降台。
- `B_UPPER_LOW` / `B_UPPER_HIGH`：上层旋转梯。
- `B_HIGH_ISLAND`：高层孤台。
- `B_EXIT_SLIDE`：出口横移台。
- `B_EXIT`：最终消防门。

### 7.4 预期解题过程

1. 在西南视角调节下层旋转梯，使其上端与中层升降台下端形成第一条青色投影接缝。
2. 点击中层升降台，人物完成第一次投影跨越。
3. 把中层升降台升到高档，人物随台到达上层旋转梯下端。
4. 在东南视角把上层旋转梯停在错误朝向时，两端位置重合但切线相同，显示橙色虚线。点击高层孤台后人物走到梯端停下，提示 `端点位置接近，行进方向没有接上。`
5. 切换上方视角并将上层旋转梯转到关键朝向，第二条接缝变为青色实线。
6. 按 `↑` 跨到高层孤台，随后让右侧待命的出口横移台从侧面滑入末档。
7. 点击消防门，人物沿真实短接进入 `B_EXIT`，两关完成。

### 7.5 难度控制

- 第一条投影接缝只在一个视角和一个下层梯朝向中成立。
- 错误重合只安排一次，且在玩家首次触发后保留橙色虚线 `1200ms`。
- 玩家卡住 `12s` 且没有输入时，仅脉冲当前可操作机关，不提示目标档位或目标视角。
- 重置只重置当前关卡，人物回到本关安全入口，不回退第一关完成状态。

## 8. 像素画风统一规范

### 8.1 渲染分辨率

- 世界层使用 `480×270` WebGL 内部缓冲区。
- 画布逻辑尺寸保持 `960×540`，仅使用整数倍最近邻放大。
- `WebGLRenderer` 关闭抗锯齿；Canvas 设置 `image-rendering: pixelated` 与 `crisp-edges` 回退。
- 设备像素比不改变世界可见范围，也不启用超采样柔化。

### 8.2 光照与材质

- 墙面、石材与机关结构继续使用 `MeshBasicMaterial`，分别消费本地 `Plaster001`、`Concrete010` 和 `Metal012` 的颜色贴图；受光面、侧面和背面仍由关卡色板离散指定。
- 三套来源均为 ambientCG 官方 `CC0-1.0` 资产。运行时只读取仓库内文件，来源、下载包、字节数和 SHA-256 记录在 `src/assets/rpg/chapter4-stair/materials/manifest.json`。
- 1K 来源图只承担纹理依据；运行时将颜色降为 `64×64` 少量灰阶明度，再由第四章色板调制。灰泥限制在 `248..255` 的低对比度范围，混凝土与金属最多使用六档。法线、粗糙度和金属度不进入运行时，避免连续 PBR 光照改变像素画风。
- 轮廓、夜窗和警示继续使用 `MeshBasicMaterial`；主色仍由固定色板调制，确保交互色不会被材质细节覆盖。
- 移除 ACES 色调映射、连续雾、软阴影、半透明毛玻璃和渐变背景。
- 阴影使用投影到地面的低分辨率色块，边缘保持硬像素；机关运动只更新阴影位置，不做实时柔化。
- 场景主色继承第四章亮色门厅：暖米色墙面、灰蓝结构、蓝绿交互色、低饱和橙色警示。夜间感通过窗外深蓝和局部冷色背面表达，主体结构保持可读。

建议基础色板：

| 用途 | 色值 |
| --- | --- |
| 深轮廓 | `#17252D` |
| 次级轮廓 | `#31444B` |
| 暖墙亮面 | `#E7D9B9` |
| 暖墙侧面 | `#BFAF91` |
| 石材亮面 | `#CBD4CB` |
| 石材背面 | `#7D908E` |
| 有效连接 | `#5FE2C2` |
| 错误重合 | `#D89262` |
| 当前选择 | `#6EB7D6` |
| 夜窗深蓝 | `#173C5A` |

### 8.3 几何与纹理

- 平台、墙、柱、台阶尺寸对齐统一世界网格；一个基础格在内部画面约占 `16px`。
- 台阶边缘、扶手和平台接缝使用 `1–2px` 深轮廓。
- 圆柱细分降到 `4/6/8` 段，避免平滑塑料感。
- 三张颜色纹理均使用最近邻放大、最近邻 mip 层缩小和零各向异性；像素缓冲保持硬边，远处细节不产生连续缩放闪烁。
- 盒体六个面的 UV 按世界尺寸缩放，默认每 `2.4` 世界单位重复一份材质；大墙、平台和单级台阶保持同一纹理密度。
- 上层投影梯的目标连接点必须落在目标平台顶面的可见边缘，禁止埋在平台内部；关卡校验同时检查顶面误差和水平边缘误差。
- 上方视角中，未接通的出口横移台与上层落点保持至少 `30px` 屏幕净空；第 `2` 档必须精确回到高层通道停靠点。横移台不得沿相机纵深方向停在上楼口后方。
- 装饰只保留消防门、楼层牌、壁灯、窗框和少量盆栽；不得遮住玩家、机关端点或投影接缝。

### 8.4 人物

- 删除球体、胶囊和三维四肢人物。
- 复用 `src/assets/rpg/player/` 的 `96×128` 三方向四帧人物图，作为始终朝向当前相机的像素 Sprite。
- 保持 `RPG_PLAYER_WALK_FRAME_MS = 90`、共享脚底锚点和统一比例；深度只改变遮挡顺序，不做近大远小缩放。
- 切换视角时根据下一段路径切换 `down/up/side` 帧；人物站定使用第 `0` 帧。
- 穿越投影边时脚底沿屏幕接缝连续移动，世界坐标在 `45%` 进度处切换到目标端点空间，画面位置不得跳变超过内部 `2px`。
- 人物静止在投影端点时遵循真实深度遮挡；只有正在跨越投影边的短动画临时置于接缝表现层，落地后立即恢复。

### 8.5 机关动画

- 旋转梯每次 `90°` 使用四个离散姿态帧，帧间可插入最多两个硬边过渡姿态。
- 升降台与横移台按内部像素整数位移，每 `60ms` 更新一次显示位置。
- 有效连接出现时播放四帧：端点点亮、短线延伸、接缝闭合、稳定实线。
- 错误连接播放三帧：橙点出现、虚线闪一次、保持弱亮。
- 完成门使用四帧开门，不使用透明度淡入。

### 8.6 UI

- 去除圆角玻璃卡、模糊和胶囊状态条。
- 使用与主 RPG 一致的深蓝黑底、米白 `2px` 边框、黄色章节号和像素字体。
- 顶部只保留关卡名和当前目标；底部只显示当前选中机关及其两个操作键。
- 三个视角按钮放在右侧纵向排列，使用小型方向图，不显示答案性文字。
- 所有触屏点击区域最小 `44×44` CSS px；可见像素按钮可以更小，但命中框必须扩大且不覆盖相邻按钮。

## 9. 章节转场设计

正式接入时，二维教学楼和三维楼梯关卡使用同一像素网格完成连续切换：

1. 人物在教学楼场景进入楼梯间门框，控制器保存来源楼层、门和朝向。
2. 门内黑色区域扩展为 `16×9` 像素块遮罩，时长 `360ms`。
3. 楼梯 Demo 从与原门方向一致的相机视角开始；人物从同一画面边缘进入，脚步相位连续。
4. 通关后消防门四帧打开，人物走入；像素块沿原门方向收起，返回目标楼层安全点。
5. 失败或重置留在楼梯关卡；返回键需要二次确认后回到来源门外，不写完成事实。

独立 Demo 只实现两关之间的消防门切换和最终完成画面，不写正式章节状态。

## 11. 错误与恢复

- WebGL 不可用时显示可读错误卡和返回链接，禁止空白画布。
- 人物纹理加载失败时使用同尺寸硬边备用人物；表面纹理加载失败时仍保留固定色与硬轮廓，不影响通关。
- 相机切换、机关移动或人物移动中收到重复输入时忽略并显示短促按钮反馈，不排队执行旧输入。
- 导航图重算后若玩家节点失效，将玩家放回最近安全节点并记录调试警告。
- 视角切换后若产生多个候选投影边，只保留关卡白名单内屏幕距离最小的一组，其余记录到调试快照。

## 12. 验收标准

### 12.1 功能

- 第一关只通过三件机关和一次投影连接完成。
- 第二关只通过四件机关、两次投影连接完成。
- 错误重合显示橙色虚线且无法通行。
- 不可达点击会走到断口边缘，人物不会停在空中或穿过实体。
- 投影边通行时相机和机关锁定，结束后恢复。
- 两关重置、关间过场、全完成和重玩均可用。

### 12.2 视觉

- 内部渲染为 `480×270`，放大后无抗锯齿和模糊边。
- 人物使用共享四帧像素资源，脚底锚点稳定。
- 机关、平台、门和 UI 使用有限色板与硬边轮廓。
- 任何视角下，玩家、端点、接缝和出口均不被装饰遮挡。
- 画面亮度与第四章亮色门厅可连续阅读，主体区域不得依赖纯黑遮罩表达夜间。

### 12.3 浏览器与输入

- Blink、Gecko、WebKit 在 `1280×720`、一个非 `16:9` 桌面窗口和 `390×844` 下完成两关。
- 桌面支持鼠标、`1/2/3`、`Q/E`、方向键和 `Space` 等价移动请求。
- 触屏支持视角、机关和场景点击，按钮无重叠，文档无横向或纵向溢出。
- 减弱动态模式可完成两关。
- 页面错误和控制台错误为 `0`。

### 12.4 构建边界

- `npm run build:chapter4-stairs3d` 生成独立单文件并能通过本地 HTTP 打开。
- `npm run typecheck` 与 `git diff --check` 通过。
- 主 `npm run build:single` 仍需等待 `src/assets/rpg/campus/zijingang_campus_plate.png` 的删除决策；本工作不得私自恢复该文件。

## 13. 开放问题

- 正式接入时两个楼梯关卡分别对应哪两个章节门，需要在独立 Demo 验收后由剧情控制器规格确认。
- 独立 Three.js Demo 只负责保留玩法与投影算法证据，不构成当前 Phaser 教学楼场景验收。
- 正式关卡是否保留关卡内“返回门外”功能，需要结合第四章循环重置规则另行确认。
