# 第四章阶段切换、演出与解谜承接设计

日期：2026-09-01

## 背景

第四章的控制器、任务条件和存档能够连续推进，但多个阶段会在一次交互成功后立即改变时间、楼层、场景与目标。现有对白由 JSON、Phaser 场景硬编码和 React Overlay 分别管理，玩家常常只看到一条结果提示，新谜题已经开始。

## 已确认方案

采用由 `RpgGameHost` 管理的阶段切换呈现协调器。`ChapterFourTemporalMazeController` 继续一次性提交全部进度事实；协调器只读取 `intentType + previousPhase + phase`，选择内容合同、暂停输入并依次展示过渡。协调器状态只存在于当前会话，不写入存档。

每个普通阶段切换包含三步：

1. 结果：说明刚完成的动作和获得的剧情事实。
2. 变化：明确时间、地点或现场状态发生的变化。
3. 解谜承接：说明新异常为何需要当前谜题，并给出一个可执行的下一动作。

过渡文本使用 `chapter4-755.content.json`。阶段名、时间状态与当前差分复用 `ChapterFourStagePresentation`，避免新增第二套阶段描述。

## 演出与解谜关系

演出只展示玩家已经触发的事实，不提前展示谜题答案。每段演出结束时必须留下可操作的现场结果，例如亮起的目标、改变的时间状态、关闭的门或新的任务目标。新任务说明只包含目标对象和第一步动作。

- 时针安装：`12:25 → 18:50`，通过两间教室与电梯历史验证同一时刻的空间记录。
- 定位盘安装：`18:50 → 22:45`，保洁车异响和停走旧钟共同引出维修谜题。
- 分针窃取：`22:45 → 07:54`，停电与缺失的一分钟引出配电网格。
- 灯光锁定：供电恢复后出现纸条逃逸，引出追逐；演出不泄露 202 的终点判定。
- 追逐结束：关闭 202 门并留下可回收投影，引出最后一分钟回收。
- 分针归位：`07:54 → 07:55`，通过校园卡与纸质签到双证据确认时间修复。
- 签到完成：确认“本人来过”，再进入现有星灯最终收束。

## 专用演出边界

序幕、Three.js 错位楼梯和星灯收束继续由既有专用组件负责。普通阶段协调器不能重复展示它们的字幕。Phaser 场景继续负责世界对象清理、玩家定位和贴图切换，不再负责跨阶段对白。

## 跳过、刷新与失败

- 允许跳过普通过渡，但最终解谜承接卡必须显示。
- 普通过渡开始时只在 `sessionStorage` 写入目标阶段标记；页面刷新后不重播结果与变化，只恢复最终解谜承接卡。玩家确认后立即清除标记，正式进度仍完全来自 `GameState`。
- 内容合同缺失时显示当前阶段、时间与下一任务摘要，同时记录开发诊断；不得阻止继续游戏。
- 页面隐藏时暂停自动计时，返回后继续当前步骤。
- 对白合同不能执行函数、提交 intent、授予物品或写入存档。

## 备选方案

1. 继续在 Phaser handler 中补字幕：改动小，仍存在多处文本来源和重复呈现风险。
2. 扩充 `syncPhaseSideEffects()`：能处理阶段进入，无法可靠区分正常切换、刷新恢复和开发者检查点。
3. Host 阶段协调器：改动集中，能够统一输入暂停、过渡顺序、跳过和恢复。本轮采用。

## 本轮范围

本轮保留现有谜题答案、步骤门槛、道具消耗、存档结构和阶段图。灯光锁定进入最终追逐后新增 `1200ms` 可移动准备期，准备期内追逐者保持隐藏和静止；追逐路线、远近速度、抓捕距离、失败重置与终点判定保持原合同。其余新增内容只负责阶段切换演出、谜题第一步说明、运行时所有权和对应验证。

## 落地后的单一所有权

- `transition_overlay`：八个普通阶段切换，统一显示结果、变化和下一步；Phaser 只同步已提交的场景状态。
- `external_overlay`：Three.js 错位楼梯与最终星灯收束，普通转场在专用演出挂载前结束。
- `scene_interaction`：阶段内反馈、距离和模式拒绝、对象清理与玩家定位。
- `controller_feedback`：缺少可视消费者的控制器结果与错误诊断。

同一结果只能选择一个呈现所有者。普通转场期间清除共享字幕并暂停 Phaser 输入；点击“开始行动”后恢复控制或挂载对应专用演出。
