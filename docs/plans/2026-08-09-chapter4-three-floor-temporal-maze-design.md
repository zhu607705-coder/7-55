# 第四章三层校园时间迷宫设计

**确认日期：** 2026-08-09

**确认方案：** C——固定真实交通核心，组合空间变化、时间重放与跨层证据依赖。

**本轮范围：** A 楼 1F、2F、3F 三张 `1672×941` 俯视像素楼层图。B 楼、A4 与独立视错觉楼梯保留扩展接口，本轮不进入可达图和任务链。

## 1. 背景与问题

当前 `ChapterFourTemporalMazeScene` 已经具备三层拼接、人物移动、静态碰撞、电梯开合和楼层切换，但仍处于地图预览状态：

- 三层的交互结构接近，缺少可辨认的楼层玩法。
- 背景中存在三扇电梯门与左右两座远端楼梯，和“一部电梯旁接一座楼梯”的真实交通核心冲突。
- 二楼开放学习区的家具与南侧边界只留下约 `8px` 间隙，人物无法从中央区域横向通过。
- 楼层切换事件没有写回 `chapter4.floor`、`roomId` 与正式检查点，刷新后无法可靠恢复。
- `chapter4MapPreviewOnly` 长期开启，任务条、明暗模式和电梯历史同步面板无法进入真实验收。
- 原六节点拓扑将 `B2/B3` 压到三张展示层，空间身份不清晰。

## 2. 设计原则

1. **真实结构固定。** 三层共用同一位置的一部电梯、一座相邻楼梯和一条始终可走的主环路。
2. **变化发生在可见支路。** 门、隔断、NPC 队列与局部通道随时间状态改变；固定主环路不被动态碰撞封死。
3. **明暗职责固定。** `深色观察` 记录历史轨迹、残影与时间窗口；`浅色操作` 执行开门、移动隔断、搭乘与进入房间。
4. **证据跨层使用。** 一楼提供时间窗口，二楼提供人员路线与导视碎片，三楼完成导视重建；回到二楼后进入新的历史窗口。
5. **视觉与碰撞同源。** 每个碰撞体都对应墙、门、家具或关闭隔断；状态改变时视觉对象和碰撞体同步切换。
6. **当前任务不泄露答案。** 任务条只说明证据类别和当前动作，不显示楼层顺序、时间答案和最终房间。

## 3. 建筑交通核心

### 3.1 单电梯

- 三层只保留中心电梯，门洞中心继续使用局部坐标 `x=836`。
- 背景中的其他电梯门改为墙面、校友展示或设备柜，且不保留交互热点。
- 左右门扇使用与楼层母图同像素密度的结构贴图，保留中心缝、门套、轿厢暗部与六档开合帧。
- 楼层选择面板位于轿厢内，背景大厅不显示悬浮面板。
- 自由乘梯与剧情电梯共用一套门动画；控制器决定可选楼层和历史窗口。

### 3.2 相邻楼梯

- 在电梯右侧设置一座连续楼梯间，三层局部坐标一致。
- 1F 只显示上行落点，2F 同时提供上行与下行落点，3F 只显示下行落点。
- 楼梯每次只切换相邻楼层；到达点仍在同一楼梯间，禁止把人物传送到大厅中心。
- 原西侧、东侧远端楼梯改为普通房门或封闭消防设备区，不再属于交通图。

### 3.3 固定主环路

- 每层从交通核心出发，都能沿大厅外圈返回交通核心。
- 2F 保留三段最低净宽：西侧纵向通道 `220px`、东侧纵向通道 `128px`、南侧横向通道 `128px`。
- 2F 南侧横向通道使用局部范围 `y=686..814`；中央休息沙发改为两组侧向座位岛，禁止覆盖此范围。
- 203 门口、开放学习区和交通核心至少有一条连续可达路线。

## 4. 三层玩法差异

### 4.1 1F：时间入口与电梯历史

**空间身份：** 主入口、麦斯威、校友头像长廊、交通核心。

**玩法目标：** 建立时间窗口并取得进入二楼的有效历史片段。

- 深色观察记录湿纸水迹、麦斯威暖风和电梯三条历史轨迹。
- 浅色操作恢复暖风，并调整电梯重放起点。
- 电梯门只在完整覆盖人物进入窗口时允许登乘。
- 成功后写入一楼时间证据和 A2 到达检查点。

一楼承担规则教学与安全返回，不增加会封死主入口的动态隔断。

### 4.2 2F：人员时刻与可变走廊

**空间身份：** 201 创客工坊、204 研讨教室、202 阶梯教室、203 计算机教室、开放学习区。

**玩法目标：** 观察人员路线，利用时间空档重建局部走廊，并取得导视碎片。

- 深色观察同时记录三组人员残影：讨论组、戴耳机学生、清楼人员。
- 观察结果标记每组人员经过的门和停留区，不显示最终路径。
- 浅色操作在对应时间空档移动两组可见隔断；隔断仅改变内圈支路。
- 走廊重建完成后，玩家可从主环路进入开放学习区并取得两块导视碎片。
- 第一次离开 2F 后，历史状态推进；再次返回时 203 门口开放新的取证窗口。

### 4.3 3F：导视重建与连廊判断

**空间身份：** 301 校史档案展、302 媒体工作室、304 报告厅、303 智慧教室、校友荣誉门厅。

**玩法目标：** 利用一楼时间证据和二楼碎片恢复导视，判断有效连廊记录。

- 深色观察在头像长廊与档案展中读取旧导视残影。
- 浅色操作把二楼取得的碎片放入三楼导视板。
- 导视板根据历史时间只恢复当前可验证的一段，不直接显示最终目的地。
- 报告厅侧门与连廊入口按时间窗口切换；错误窗口保留可见关闭门和纠正提示。
- 完成后要求玩家返回 2F，形成第一次跨层回访。

## 5. 跨层闭环

1. 1F 观察并校准电梯历史，记录到站窗口。
2. 乘电梯到 2F，观察人员动线并重建内圈支路。
3. 从 2F 取得导视碎片，经相邻楼梯到 3F。
4. 在 3F 结合时间窗口和导视碎片，确认有效历史连廊。
5. 返回 2F；此前关闭的 203 取证窗口进入可操作状态。
6. 该窗口完成后再接入后续 B 楼拓扑，当前切片在此保存安全检查点。

这条路线要求玩家至少使用一次电梯和两次楼梯，并回访已改变状态的楼层。

## 6. 状态与数据流

- `ChapterFourTemporalMazeController` 继续作为进度权威。
- 复用 `phase`、`solvedPuzzleIds`、`clueIds`、`buildingTimeSeconds`、`floor`、`roomId` 和 `rpgCheckpoint`。
- 场景局部只保存门动画进度、NPC 当前帧、提示计时和输入状态。
- 新增纯选择器 `ChapterFourMazeProjection`，根据控制器事实生成：
  - 当前楼层可见 NPC 与残影；
  - 可操作门和隔断；
  - 动态碰撞矩形；
  - 可见交互目标；
  - 当前安全重进点。
- 自由电梯和楼梯切层必须通过控制器提交移动意图，随后同步 `floor`、`roomId`、`rpgCheckpoint` 并触发自动存档。
- `A1/A2/A3` 与展示层 `1/2/3` 一一对应；`B2/B3/A4` 不再压入展示层映射。

## 7. 反馈与失败处理

- 错误模式：说明需要切换到观察或操作模式。
- 距离不足：显示目标名称和需要站到的可见站位范围。
- 缺少证据：说明仍缺哪一类证据，不给出所在楼层和答案。
- 时间窗口错误：门保持可见关闭状态，显示下一步应重新观察或调整重放。
- 动态隔断关闭：动画先完成，碰撞随后启用；打开时碰撞先关闭，动画随后完成。
- 所有失败保持当前楼层、道具与已记录证据，不回退已完成谜题。
- 交互目标当前不接受空格键时，HUD 不显示空格键提示。

## 8. 视觉合同

- 三张楼层图维持 `1672×941`、俯视正交、硬边像素、统一光向和像素密度。
- 电梯、楼梯、房门、隔断、NPC 与碰撞边缘按源像素校准。
- 模式切换只改变动态对象、残影与局部色层，禁止整张地图换成无法辨认的滤镜。
- 交互标记只在目标激活且人物进入邻近范围时出现。
- 主环路保持清晰地面材质；禁止用不可见碰撞制造路线变化。

## 9. 验收标准

1. 1F、2F、3F 各有一张独立母图、一个交通核心和一个可返回的主环路。
2. 每层只出现一部可操作电梯，电梯旁存在同位置的连续楼梯。
3. 2F 人物能从交通核心走到 203 门口、开放学习区及南侧横向通道，全程无隐形墙。
4. 1F、2F、3F 分别完成时间校准、人员路线、导视重建三种不同交互。
5. 至少一次跨层回访会改变已访问楼层的门、NPC 或支路状态。
6. 刷新页面后恢复楼层、检查点、模式、已记录证据和已完成谜题。
7. 桌面键盘和移动端触控均可完成电梯、楼梯、模式切换和三层闭环。
8. Blink、Gecko、WebKit 在 `1280×720`、一个非 `16:9` 桌面视口和 `390×844` 下无页面错误、控制台错误或文档溢出。
9. `npm run typecheck`、`npm run chapter4:validate-topology`、`npm run build:single` 和定向单文件检查通过。

## 10. 备选方案与取舍

- **仅空间变化：** 画面反馈直接，跨层时间主题较弱，未采用。
- **仅时间重放：** 状态逻辑清晰，地图本体变化不足，未采用。
- **空间变化与时间重放组合：** 能同时区分三层用途、支持跨层回访，并保留固定安全主路，已确认采用。

## 11. 开放问题

- B 楼、A4 与视错觉楼梯的正式接入时间尚未确定；本设计只保留控制器和拓扑接口。
- 楼层母图的交通核心需要重新出图或进行同源像素编辑；最终资源必须逐张检查楼梯、电梯、门口和主环路的透视与净宽。
