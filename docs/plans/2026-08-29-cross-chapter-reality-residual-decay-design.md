# 2026-08-29｜跨章节现实模式与独立残影消散设计

## 1. 背景

食堂、剧院、启真湖和第四章已经使用同一组现实模式语义：`深色观察`读取线索，`浅色操作`执行实体动作。当前各场景的模式视觉、残影持续方式和刷新行为仍由场景分别处理，导致同一种交互在不同章节里具有不同反馈；第四章若直接加入倒计时残影，还会进一步扩大这种差异。

本设计选用“每条线索独立衰减”。它同时覆盖第三章横屏 RPG 的食堂、剧院、启真湖和第四章教学楼。第三章的照片、录音、微信、网络等手机证据属于永久档案，不进入残影计时；玩家一旦保存，证据继续由控制器和存档持有。

## 2. 已选方案

每个可观察目标拥有独立的残影运行记录。玩家在深色模式观察目标时，当前目标以完整历史形态显示，并刷新自己的可见时长；切换到浅色模式后，该残影覆盖在现实物件上，先稳定保留，再逐段减弱并完成像素化消散。其他目标的时间和透明度不受影响。

选用该方案的原因：

- 食堂、剧院、启真湖和第四章可以共享一个运行时合同，同时保留各场景自己的美术对象。
- 多条线索支持任意调查顺序，重新观察一个目标不会重置其他目标。
- 时间、空间和布局类谜题可以使用不同的可见时长。
- 永久调查事实与临时视觉记忆保持分离，存档不会保存倒计时、透明度或正在播放的消散帧。

## 3. 现实模式交互顺序

### 3.1 模式职责

- `深色观察`：读取残影、路线、节拍、时间差和异常状态；观察目标会写入永久调查事实，并刷新该目标的临时视觉残影。
- `浅色操作`：拾取、拖放、清洁、支付、推动、开关设备和使用物品；正确动作继续验证当前物品、距离、目标、房间和剧情阶段。
- 两个模式的入口在目标所属剧情阶段内同时保留。错误模式尝试会显示当前动作属于哪一种模式，不消耗物品，也不改变调查结果。

### 3.2 不设置固定模式顺序

- 独立目标之间没有强制顺序。玩家可以先看菜单残影，也可以先检查取餐窗口；可以先观察 Room 204 的东区，也可以先观察西区。
- 同一目标的实体动作不得只因“尚未观察”而锁定。玩家若已经从其他证据推断出正确答案，可直接在浅色模式尝试；正确动作由控制器接受。
- 完成实体动作后，深色观察入口仍然存在。此时显示历史状态覆盖在当前结果上，玩家仍可补记证据。
- 最终结算可以检查一个无序事实集合，例如“布局正确 + 三个区域均已记录”；中间步骤不能借此恢复 `深色 → 浅色` 固定链。
- 手机证据矩阵继续支持任意应用顺序；它与现实模式残影共享“调查顺序不构成门槛”这一规则，但不共享临时视觉寿命。

## 4. 共享运行时合同

新增一个不进入 `GameState` 和 `SaveStore` 的运行时记录模块：

```ts
type RpgResidualStage = "stable" | "weakening" | "dissolving" | "expired";

interface RpgResidualSpec {
  id: string;
  sceneId: string;
  durationMs: number;
  stableRatio: number;
  weakeningRatio: number;
  refreshPolicy: "on_observe";
  visualProfile: "route" | "object" | "time_track" | "room_layout";
}

interface RpgResidualSnapshot {
  id: string;
  remainingMs: number;
  progress: number;
  stage: RpgResidualStage;
  alpha: number;
  ditherAmount: number;
}
```

运行规则：

1. 第一次成功观察创建记录；重复观察把该目标恢复至完整时长。
2. 深色模式下目标保持完整可读，倒计时冻结。
3. 切到浅色模式后开始消耗该目标自己的 `remainingMs`。
4. 对话、任务抽屉、物品栏、手机覆盖层、加载、场景切换和页面隐藏期间暂停。
5. 玩家失去控制的演出、追逐结算和小游戏原子阶段暂停。
6. 离开所属 RPG 场景后清理临时记录；永久调查事实继续保留。再次进入时可重新观察恢复画面。
7. `expired` 只移除视觉层，不撤销已经完成的操作、调查事实或最终解谜条件。

## 5. 消散表现

### 5.1 已批准的跨章节色彩合同

采用 A 方案：浅色模式保留原场景暖色和金色操作点，深色模式继续使用深蓝环境与荧光蓝线索。

| 视觉职责 | 统一色值 | 使用规则 |
|---|---|---|
| 深色最暗边缘 | `#020B16` | 边缘暗角、扫描边界，不覆盖 HUD |
| 深色环境基准 | `#06142D` | 场景压暗层的基准；食堂、剧院和第四章可保留已有相邻深蓝色，但不得转为纯黑或灰色 |
| 荧光蓝主体 | `#67DDFF` | 残影轮廓、路线、圆形观察锚点和扫描线 |
| 荧光蓝高亮 | `#9AEAFF` | 核心像素、交叉点、短时读取反馈 |
| 荧光蓝低阶 | `#3BC5EF` | 外围光、弱化阶段的次级轮廓 |
| 浅色暖层 | `#FFE2A6` | 仅使用 `0.04–0.08` 的低透明覆盖，不改变原场景材质色 |
| 金色操作点 | `#FFD36F` | 菱形操作锚点、实体动作边框 |
| 金色高亮 | `#FFE8AE` | 操作确认核心与短时反馈 |

深色模式的整场压暗层只在深色观察期间存在。切回浅色操作后，压暗层在 `420ms` 内退场，已观察残影继续以荧光蓝覆盖在暖色现场上。荧光蓝残影不得在浅色模式中改成金色；金色只表示可以执行的实体动作。

颜色之外继续使用形状区分：深色观察点为圆形，浅色操作点为菱形。色觉差异、低亮度屏幕或单色截图中仍能判断两种模式。

### 5.2 消散颜色曲线

残影消散只降低发光强度、轮廓完整度和像素覆盖率，荧光蓝色相保持稳定：

- 稳定阶段：核心使用 `#9AEAFF`，主体轮廓使用 `#67DDFF`，外围光使用 `#3BC5EF`。
- 减弱阶段：核心逐步收缩到 `#67DDFF`，外围光 Alpha 降低，轮廓开始出现像素缺口。
- 消散阶段：剩余像素在 `#67DDFF` 与 `#9AEAFF` 间保持明暗层次，禁止向灰色、白色或金色漂移。
- 消失以后：只保留低亮度蓝色圆形观察锚点；目标本身和金色浅色操作点继续按当前玩法条件显示。

### 5.3 时间表现

玩家界面不显示数字倒计时，时间变化通过残影视觉表现：

| 阶段 | 进度区间 | 视觉状态 |
|---|---:|---|
| 稳定 | `0%–55%` | Alpha 从 `0.92` 缓慢降到 `0.78`；轮廓、文字和轨迹保持完整 |
| 减弱 | `55%–80%` | Alpha 从 `0.78` 降到 `0.42`；边缘出现规则像素缺口，扫描纹理逐步断开 |
| 消散 | `80%–100%` | Alpha 从 `0.42` 降到 `0.08`；按 `2×2`、`4×4` 像素格分批隐去，末段持续约 `900ms` |
| 消失 | `100%` | 移除残影内容；目标本身仍可交互，深色观察可重新刷新 |

补充规则：

- 模式切换使用 `420ms` 交叉过渡。切到浅色时，深蓝环境层先退出，荧光蓝历史层保持一个完整画面，再进入对应目标的当前衰减阶段；浅色暖层和金色操作点同步进入。
- 消散使用稳定的像素遮罩，不采用高频闪烁。普通模式允许幅度不超过 `0.04` 的低频明暗变化。
- `prefers-reduced-motion` 下取消脉冲和逐格飞散，使用三个静态透明度台阶和一次短切换。
- 残影层、像素碎片和扫描纹理始终不参与碰撞与遮挡判定，并处于玩家角色层以下。
- 临近消失时只显示“残影正在减弱”这一类状态，不显示剩余秒数，也不自动切换模式。

## 7. 场景接入边界

- `RpgInteractionContract.ts` 继续管理目标、距离、模式和错误类型；残影寿命配置与状态计算由独立模块管理。
- `RpgGameHost.tsx` 提供统一的暂停上下文，避免四个场景分别判断对话框、物品栏或任务抽屉是否打开。
- `CanteenInteriorScene.ts`、`TheaterInteriorScene.ts`、`QizhenLakeScene.ts` 和 `ChapterFourTemporalMazeScene.ts` 只把已有残影对象绑定到共享快照，不拥有第二套计时器。
- 控制器继续持有永久事实和终态结算；Phaser 仅提交观察事件、显示衰减快照，不写存档。
- 手机证据、照片和已保存截图不做消散。它们是玩家可以长期回看的记录，避免残影消失后只能依赖短时记忆。

## 8. 异常与恢复

- 观察事件成功但视觉对象尚未加载：记录待刷新状态，资源就绪后从完整阶段开始，不从加载耗时中扣减。
- 场景切换中断：清理临时残影并取消 tween；永久事实不回滚。
- 页面隐藏或系统暂停：冻结 `remainingMs`，恢复后从同一数值继续。
- 残影消失时正在拖拽：拖拽继续完成；消散只影响提示层，不取消已经开始的浅色动作。
- 同一个目标被连续观察：幂等写入永久事实，同时每次刷新临时残影。

## 9. 验证边界

本轮不新增测试文件、测试依赖或专用 validator。实现完成后仅使用现有工程门禁和真实浏览器手动路径：

- `npm run typecheck`
- `npm run build:single`
- 食堂、剧院、启真湖、104／105、电梯、导视板、Room 204、维修和配电的现有 DEV 检查点

## 10. 备选方案与拒绝原因

### 全局统一倒计时

一次切换后所有残影共同消失。实现简单，但会把多目标调查重新变成固定路线，并使重新观察一个目标错误地刷新全部线索。

### 基于距离的残影消散

离开目标越远越快消失。它适合个别追踪路径，不适合 Room 204、电梯时间比较和配电等需要往返查看的谜题，也会使同一规则在不同地图缩放下产生不一致体验。

## 11. 开放项

当前没有阻塞实施的产品问题。时长表在首次真实浏览器试玩后允许整体微调，但以下规则保持固定：不显示秒数、每条线索独立、模式顺序不构成门槛、永久事实与临时视觉分离、深色使用深蓝与荧光蓝、浅色使用原场景暖色与金色操作点。

### 12.3 模式与顺序规则

- 同一阶段的目标可任意调查。例如 A1 的 104、105、电梯和值班牌没有界面上的强制点击顺序；离开 A1 时只检查阶段事实是否齐全。
- 301 与 302 可以先后到访。玩家未取得胶片时仍可在 302 观察扫描台和地标残影，但无法提交对齐结果；取得胶片后不要求重新按固定路线进入房间。
- 201、203 与开放自习区可任意完成。各自的永久事实独立保存，回到浅色或深色模式都不会丢失已完成分支。
- 深色只读取痕迹和关系，浅色只执行摆放、校准、连线和确认。操作先行时可以先整理控件；需要观察资料的最终提交由控制器给出明确缺失项，不重置玩家已经完成的局部输入。
- 新增谜题只写六个控制器事实，不持久化拖拽位置、面板动画、临时选中项或残影倒计时。

### 12.4 视觉素材合同

六个插入点使用独立透明底像素素材，放置在原 `1672×941` 母图上方，不改母图、不制造额外碰撞。正式素材包括：A1 值班签到板、A3 胶片索引抽屉、A3 对齐扫描台、A2 定位板校准夹具、A2 五区拓扑终端、A2 疏散路线板。

每张素材必须：

- 以相应 A1／A2／A3 母图作为风格参考生成，保持俯视三分之四像素视角、暖色室内光向和木质／金属材质比例。
- 保留真实 Alpha；禁止白底、棋盘底、文字水印和烘焙阴影背景。
- 先裁去透明空白，再使用整数或接近整数的等比缩放适配目标台面；最终显示尺寸由单一放置表管理。
- 只提供看得见的交互对象，热区按缩小后的实际轮廓标定。碰撞体积不得大于可见物件轮廓。
- 深色模式在素材上叠加荧光蓝残影轮廓，浅色模式显示原暖色素材和金色菱形操作点；人物层仍高于残影与解密锚点。

### 12.5 控制器事实与门槛

新增永久事实固定为：

- `a1_duty_board_reconstructed`
- `a3_archive_film_retrieved`
- `a3_media_alignment_completed`
