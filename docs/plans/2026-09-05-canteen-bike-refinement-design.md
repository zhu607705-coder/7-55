# 食堂至剧场自行车与沿途环境重做

## 背景与选择

用户要求自行车整体重做、精细建模并拉长流程，随后补充两侧场景和人物一起重做；最终明确“不要参考之前任何的风格，直接自己重新做”。本次重新定义全部视觉：GitHub 授权骨骼人物、蓝色上衣与炭灰长裤、橄榄绿通勤自行车、浅灰金属和织物材质、现代低层校园建筑、自然绿化及柔和日照。旧造型、旧配色、旧场景风格均不作为参考。保留程序接口、操控和剧情事实。

既有方案正常无碰撞理论用时约 19.67 秒。当前模型已有较多几何，但后视构图遮住车架、环境以重复方块和硬边树冠为主；单纯增加面数不足以满足本次要求。

## 设计

2026-09-05 追加要求：先修正反向蹬踏，再改用 GitHub 上已有的人物素材。程序化人体外观停止使用；接入有可核对授权的 Quaternius 骨骼模型，人物源文件保持原样。现有车把、脚踏和上下车约束继续作为动作目标，实际可见骨骼必须完成接触与朝向验证。骑手与沿途行人共享素材加载与骨骼复制机制，离线单文件不得请求远程模型。

人物追加约束：主角上衣必须为明确的蓝色，深色长裤；骑行、上车与下车均复用同一材质变体。仅在运行时修改服装材质颜色，不编辑 GitHub 原 GLB 字节。

18:48 追加修订：当前实玩仅约 5 次变道，紧张感不足；改成有明确空车道的错位障碍组，前段教学、主路连续避让、施工交错通行、末段紧凑冲刺，保留约 90 秒总时长。先逐相位侧视/前视复现腿部问题，检查真实蒙皮的膝盖朝向、胯部与脚踝连接，再修改骨骼；接触点数值不能单独作为人体视觉验收。

1. 骑行主体：重做可辨认的管状车架、圆形轮胎与轮圈、辐条、传动、刹车线、车灯、车篮与挡泥板；所有可见自行车采用统一结构。调整骑手头身视觉比例、衣物与背包轮廓；保留共享 rig 的手握把、脚踏板、上下车动作和单一模型来源。
2. 沿途环境：独立设计食堂出口的轻型雨棚与停车区、林荫主路的非均匀树冠与开放式教学楼、施工段的波纹围挡与管材、剧场前广场与折线屋顶公共建筑。道路具有路缘石、铺装接缝、排水细节、浅色标线与柔和接触阴影。景观遵循各段的空间布置，禁止机械重复整块楼体；本段为独立展示场景，不代表校园地图测绘数据，不改变正式地图资产。
3. 节奏：755 米、3 次机会保持；分段目标约 24/23/23/20 秒，共约 90 秒可操作时间，不含上下车。障碍按路段组织，间距留出反应和换道时间，施工段至少留一条通路。短暂碰撞与暂停不改变证据、支付或终章事实。
4. 渲染：使用现有 Three.js，无新增引擎/远程依赖；按材质合并静态几何，装饰物不会成为隐藏碰撞体。低能力设备保留现有 2D 回退并使用同一距离与碰撞规则。验证明确标记实际后端，不能用回退截图验收 Three.js 画面。
5. 交接：遵循 2026-08-23 原生上车 → 0–755 实玩 → 原生停车下车 → 剧场外检查点合同。旧 Hailuo M1 已拒绝、M2 未批准，不复用、不新发付费生成任务。

## 方案比较与边界

采用上述精细化原生模型以保证运行与交接一致性。完全写实贴图/复杂实时后期将增加移动端成本，本次不采用。仅改变车体颜色或延缓距离计数不能满足整体重做及段落变化要求。

## 验收

实际 Three.js 在桌面与手机视口目检四段、静止/踩踏/转向、上车和下车；记录绘制调用、几何、帧耗时及手脚接触误差。通过真实键盘/触控完成 0–755 米，核对约 90 秒、失败重试、暂停恢复、重新载入和剧场交接。运行既有依赖轻量合同、TypeScript、发布构建及离线单文件；临时截图检查后清理。所有结果完成前均为待验证。
