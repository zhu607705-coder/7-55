# RPG 交互契约

## 目标

所有横屏 RPG 场景使用同一套可推断规则。玩家只需判断当前模式、与真实物体的距离、道具名称和可见落点。人物朝向与皮划艇航向只控制移动和表现，不参与任何交互验收。

## 模式规则

| 当前模式 | 允许行为 | 不允许行为 |
| --- | --- | --- |
| 深色观察 | 读取残影、异常、路线、节奏、隐藏文字 | 拾取、拖放、清洁、付款、推动、扫描、启动设备 |
| 浅色操作 | 移动、拾取、拖放、清洁、付款、推动、扫描、启动设备 | 读取仅在深色模式存在的线索 |

模式切换控件同时显示：

- 当前模式，例如 `当前：深色观察`
- 切换结果，例如 `切换：浅色操作`

## 空间目标字段

`RpgSpatialInteractionTarget` 是 Phaser 场景、React 物品栏和运行时调试状态的共同结构。

- `x / y`：可见设备或槽位中心。
- `width / height`：源图中真实物体边界，人物距离从脚点量到最近边缘。
- `dropWidth / dropHeight`：道具必须进入的精确矩形。
- `stand`：仅供出生点、表演落位或推车把手动画使用，不参与通用交互验收。
- `proximity`：人物脚点到物体最近边缘的最大距离。
- `acceptedItem`：该目标接收的唯一道具。
- `requiredMode`：支持现实模式的物理操作固定为 `light`。
- `label`：反馈、无障碍名称和调试数据使用的同一可见名称。

判定顺序：

1. 松手点是否进入当前阶段的目标框。
2. 道具是否匹配该目标。
3. 当前模式是否满足目标要求。
4. 人物是否进入物体的最大交互距离。
5. TypeScript 控制器是否认可剧情状态。

前四项由共享空间契约给出明确反馈，第五项保留给剧情控制器。任何场景、目标数据、运行时证明或控制器都不得恢复朝向门禁，也不得返回 `wrong_facing`。

## 当前精确交互

- 东区大食堂：取餐窗口、饮料机、瓶罐架、混合台和餐车只检查真实边界距离与当前阶段。
- 图书馆：入馆记录设备、前台、检索终端、打印机、书架、书包、纸条与桌面夹缝使用实际物体边界，不检查人物方向。
- 剧院：海报、取票机、闸机、灯控台、通风口和节目单残页只检查距离、模式、道具和阶段。
- 启真湖：柜门、船架、水纹、天鹅和浮排使用各自实际边界；人物姿态和船头航向不影响交互。
- 最终教学楼：断续水迹、卷帘门、主电梯、楼梯、旧钟和所有剧情目标均不检查人物方向。

## 前置条件压缩

- 食堂三只异常餐盘同时呈现同类蓝色残留。一次有效深色观察记录三只目标，浅色回收顺序自由。
- 剧院三张节目单在浅色模式可按任意顺序取得。全部取得后，深色观察提供有信息价值的排序线索。
- 启真湖和图书馆保留会改变答案含义的前置条件；单纯重复操作不作为解锁条件。

## 网页运行时

- TypeScript 模型是交互目标数据源。
- Phaser 读取同一 `label`、`width`、`height`、`proximity`、`dropWidth`、`dropHeight`、`acceptedItem` 和 `requiredMode`。
- Phaser 只提交意图，TypeScript 控制器继续拥有剧情、物品、钱包、任务和存档状态。
