# RPG 交互契约

## 目标

所有横屏 RPG 场景使用同一套可推断规则。玩家只需判断当前模式、人物站位、道具名称和可见落点，不需要猜测场景内部的特殊判定。

## 模式规则

| 当前模式 | 允许行为 | 不允许行为 |
| --- | --- | --- |
| 深色观察 | 读取残影、异常、路线、节奏、隐藏文字 | 拾取、拖放、清洁、付款、推动、扫描、启动设备 |
| 浅色操作 | 移动、拾取、拖放、清洁、付款、推动、扫描、启动设备 | 读取仅在深色模式存在的线索 |

模式切换控件同时显示：

- 当前模式，例如 `当前：深色观察`
- 切换结果，例如 `切换：浅色操作`

## 空间目标字段

`RpgSpatialInteractionTarget` 是 Phaser fallback、React 物品栏、运行时调试状态和 Godot 同步数据的共同结构。

- `x / y`：可见设备或槽位中心。
- `dropWidth / dropHeight`：道具必须进入的精确矩形。
- `stand`：人物脚部需要到达的地面位置。
- `proximity`：相对 `stand` 的允许距离。
- `acceptedItem`：该目标接收的唯一道具。
- `requiredMode`：支持现实模式的物理操作固定为 `light`。
- `label`：反馈、无障碍名称和调试数据使用的同一可见名称。

判定顺序：

1. 松手点是否进入当前阶段的目标框。
2. 道具是否匹配该目标。
3. 当前模式是否满足目标要求。
4. 人物是否到达目标的可站立位置。
5. TypeScript 控制器是否认可剧情状态。

前四项由共享空间契约给出明确反馈，第五项保留给剧情控制器。

## 当前精确交互

- 东区大食堂：`0755 取餐号` 拖入 1、2、3 号窗口各自的验票槽；人物同时站在对应窗口蓝色站位。正确流程为深色观察 3 号窗口残影，再切回浅色操作。
- 剧院：临时观演票分别拖入入口读票器和后台票据扫描器；两个位置都有独立框和站位。
- 启真湖：假纸条拖入公告栏、桥影或路灯前的独立夹位；三个候选点不再共享一个大半径。
- 图书馆：索书号、物品识别报告、右移箭头和离座 PASS 分别使用书架、盖章机、桌面夹缝和书包的独立框与站位。

## 前置条件压缩

- 食堂三只异常餐盘同时呈现同类蓝色残留。一次有效深色观察记录三只目标，浅色回收顺序自由。
- 剧院三张节目单在浅色模式可按任意顺序取得。全部取得后，深色观察提供有信息价值的排序线索。
- 启真湖和图书馆保留会改变答案含义的前置条件；单纯重复操作不作为解锁条件。

## 引擎同步

- TypeScript 模型是交互目标数据源。
- `npm run godot:sync` 把剧院模型导出到 `godot/data/theater-runtime.json`。
- Godot 读取同一 `label`、`stand`、`dropWidth`、`dropHeight`、`acceptedItem` 和 `requiredMode`。
- Godot 只提交意图，TypeScript 控制器继续拥有剧情、物品、钱包、任务和存档状态。
