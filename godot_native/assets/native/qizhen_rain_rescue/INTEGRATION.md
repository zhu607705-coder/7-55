# Production presentation adapter

PR145 sample art is copied byte-for-byte into this namespace. Original licenses, generation prompts, sampling metadata and provenance are retained beside the art. No new redistribution license is granted.

The production renderer is deliberately different from the sample: its input, process, replay, preview callbacks and preview UI are removed. The static timeline keeps the authored poses and contact geometry. `RainSession` alone supplies the monotonic cinematic clock, including focus pause accounting. The existing 5650 ms route already presents the wind and capsize. Native drawing therefore starts at source time 2650 ms (the SPLASH boundary / hold_hull phase) and continues for the remaining 12350 ms to the same 15000 ms safe-wet ending. It never replays the sample’s wind or fall. Normal route + continuation + original 1600 ms dock hold totals 19600 ms; the original video retains its 5875 ms minimum and 9000 ms watchdog. Skip and reduced motion still require the original dock hold and retained controller session before returning to the dorm.

Run `node godot_native/tests/verify_rain_rescue_native_source.mjs` from the repository root after any sample or adapter change. It verifies every copied byte, the source and adapter hashes, static geometry, namespaced dependencies and removed preview authority. A deliberate visual change requires reviewing the diff and updating the matching manifest hashes; do not regenerate the manifest merely to silence a mismatch. The portable native project does not depend on the sample directory at runtime.

Compact embedding keeps the 960×540 scene and original caption strings. Only the production renderer can suppress its footer text and expose the current caption. The outer presenter uses the same existing footer for at most two centered lines at 14–16 physical pixels, including route/capsize/dock messages. Desktop drawing is unchanged. The skip button separately preserves a 44-pixel physical touch height and at least 16-pixel text.

For a real-time desktop recording, run `bash godot_native/tools/record_rain_rescue.sh OUTPUT_DIRECTORY` on an X11 display (for example under `xvfb-run -a -s '-screen 0 1280x960x24'`). It records 24 real seconds, including the unchanged route, native rescue, dock hold and final scene. It first positions the client at `(0,0)`, checks its actual X11 rectangle with `xwininfo` against Godot's window/root render dimensions, then starts the session only after ffmpeg has captured a frame. The final scene stays open until capture ends. Root-space and capture-space assertions cover the full renderer caption glyph bounds plus padding, the route/dock Label bounds, and the entire cinematic frame. This prevents the larger X11 screen's centered-window offset from silently cropping a 1280×720 recording. The output includes verified window geometry, internal screenshots, and video frames at 0/5/10/18 seconds and the end.
