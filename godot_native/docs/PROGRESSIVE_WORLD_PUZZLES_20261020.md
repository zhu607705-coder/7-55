# 北教与启真湖：逐步建立规则的实体关卡

本轮用户范围：北教接入两处现有装置；启真湖先做码头可重玩的转运支线，验证玩法后再决定是否成为主线必过关。实现属于独立 Godot 原生运行时，不改变保留的 TypeScript / React / Phaser 版本。

## 参考与取舍

设计参考为飞书《沉星之序｜关卡设计与美术学习手册》：
<https://zju-xlab.feishu.cn/wiki/GRXvwXCI2iQatikntDUcKbIknxe>。
本轮通过已登录的飞书客户端导出文本并阅读，原始导出只保留在本机，不加入仓库。文档中的图片签名、登录参数与个人会话信息不进入实现或交付。

参考文档确认范围是 P1–P38；P39 只包含部分视觉记录及后续语音记录，不能据此宣称完整玩法验证。以下是对设计方法的归纳，不是逐关复制，也不把攻略播放时长当成游戏难度或通关时间。

- 基础动作先有可观察的结果，再引入位置限制。P2 的占位与代替关系说明：角色离开后机关会怎样变化，应该在场上直接可见。
- 物件送达与操作者完成工作是两个条件。P22、P29、P35 提醒检查操作侧、返程和最后离场，避免“目标格亮了就直接胜利”。
- 通路同时影响人和工具。P32、P33 提醒检查工具是否过得去，以及临时搭建是否妨碍后续回收；工具必须可取回，不能只检查玩家能经过。
- 在增加限制前提供撤销与当前阶段重开。反馈先说明刚发生的变化；更深提示由玩家主动请求，不默认写出坐标、按键时长或完整解法。

## 接入与推进

| 实体入口 | 活动标识 | 学习与验证目标 | 原剧情关系 |
| --- | --- | --- | --- |
| 北教 A2 的 203 拓扑终端 | `power_topology` | 观察占位如何改变连接，再处理通路与操作侧，最后完成交接与离场 | 保留 `a2_power_topology_recovered`，由原控制器核验最终连接值 |
| 北教 A2 开放自习区疏散路线板 | `evacuation_route` | 先走通一段，再识别次序与回收限制，最后完成整条路线并离场 | 保留 `a2_evacuation_route_confirmed`，由原控制器核验最终路线值 |
| 启真湖小码头转运台 | `lake_logistics` | 在低成本场景中练习转运、通路与工具回收 | 可重玩支线，无主线门槛，无新奖励、物品、存档字段 |

每个入口有三个内部阶段：建立关系、增加一种约束、组合运用。北教两处入口仍可按任意顺序游玩，因此各自提供基本操作说明，不要求先完成另一关。内部阶段不是新的章节，也不改动既有四关错位楼梯。

两个北教装置保留旧存档已完成事实。新活动需要实际行动记录与当前控制器签发的会话；简单提交旧表单答案不能跳过实体玩法。模型回放判断目标和出口，控制器核对原有最终值，再提交剧情事实。界面动画、局部提示、阶段按钮不写剧情进度。

码头支线从码头陆地上的实体目标进入，受现有场景、距离与浅色操作规则约束。转运棋盘不移动真实皮划艇或码头角色；退出后返回现场。支线成功、取消、重玩均不得改变湖区阶段、检查点、材料、钱包、追逐或 3.5 章衔接。

## 验收边界

验收需要覆盖：每一阶段可解；局部目标完成但角色未离场不能过关；错误移动、撤销、重开和主动提示；空记录、重复结果及失效会话拒绝；切换现实模式后旧会话不能恢复；旧完成事实保持；码头重复游玩不影响主线；桌面键盘、触控、窗口尺寸、暂停和退出。

本文件记录设计与验收要求。已完成验收的来源、文件摘要和范围见 [验收索引](PROGRESSIVE_WORLD_PUZZLES_ACCEPTANCE_20261020.json)，详细经过另记在 `progress.md` 与隔离的验证产物中。92 个关联原生阶段先于最后竖屏排版调整；最终排版另经 UI 56 项、Main 360 项、连续四章流程及实际三种浏览器复验。测试入口存档是明确的验收准备，不等于人工从头玩完，也不代表物理手机或最低浏览器版本验收。
