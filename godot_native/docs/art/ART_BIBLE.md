# 《7:55》像素美术规范 v1.1 · 细像素修订

执行配置为同目录的 `art_direction_v1.json`。自2026-10-21起，新绘与重建素材共用本规范；旧素材逐批登记、对照和替换，不能把“规范已建立”写成“全项目已统一”。类型沿用现代校园叙事解谜，目标沿用Godot桌面与网页、手机。未另行指定的宣传构图也使用这套校园、角色和色板。

2026-10-21后续用户要求将像素边长缩至原来的约20%。新素材采用约5倍线性细节密度：保留构图尺寸和人物比例，在更细的原生格网上重绘衣褶、木纹、绣边与动作轮廓。不能把粗像素简单放大后称为精细化。此前160×160晨光图是已验收的粗像素批次，保留其验收记录；它不再是新素材的密度目标。

## 画法与空间

世界以正交斜俯视图块组织：地板有可见面积，墙、门、桌、床保留正立面，人物竖直站立。平行边保持平行，不引入消失点或菱形等距格。相邻物件不得各用一个观察角度。题材依旧是现代校园；田园或奇幻装饰不能代替透视规则。

保持现有镜头与移动。北向校园、室内与湖面使用各自已经标定的源坐标；剧场到湖的侧向过渡仍是独立镜头，第四章已批准的空间楼梯仍沿用原表现。它们共享像素、色阶、轮廓与光照规则，不能将两种地图的坐标合成一张图。开场和宣传画按斜俯视构图重建，旧床边大脸近景仅作为晨光概念存档。

## 色板、轮廓与材质

锁定原创 **755-campus-morning-32**，32个RGB色值见JSON；每种材质最多4阶。旧粗像素角色预算12色，新细像素角色最多24色、整景最多32色。暗部偏蓝灰，纸与晨光偏暖。相同材质复用同一条色阶，不给每个物件另配渐变。

| 材质 | 四阶色值（暗→明） | 画法 |
| --- | --- | --- |
| 金属/墨色 | 202B35 /344452 /526B7A /7993A1 | 大暗面、1像素亮边；不画连续镜面渐变 |
| 木材 | 44332D /70503B /A1744E /C79B62 | 顺结构的短色簇；边角亮1像素，纹理不能盖过轮廓 |
| 墙面/石砖 | 766E63 /A39B87 /C5C1A9 /E8E0C8 | 大平面，接缝少而稳定，地砖边界不伪装成台阶 |
| 蓝布/水体 | 243F5A /385B79 /547F9D /83A7B6 | 被子用成片折面，水面用稀疏横向短纹，不加细密噪点 |
| 皮肤 | 6F483E /A76A4C /D89C6A /F0C895 | 保留脸与手的轮廓，脸部亮度低于阳光下的被子 |

新透明道具仅使用0或255透明度；半透明效果可用0/85/170/255四级。色簇至少承担形体、材质或交互信息，不能靠随机单像素撒点制造“像素感”。照片、文献与真实人物证据保留信息完整，放入统一像素边框；文字不烘焙进低分辨率底图。法线属于线性数据纹理，不套32色板。

2026-10-23纹理密度修订：后续新绘与重绘适度减少细碎的点状纹理，收敛孤立单点噪点。优先用连续的大色簇建立明暗与体积，再用顺应物件结构的成组纹理表现木纹、布褶、砖缝等材质；局部细节服务于形体、材质辨识与交互状态。单点高光只用于确有形体或状态意义的位置。按实际桌面、手机显示检查，背景纹理应安静，轮廓、可行走面和可交互物件先读清。这项修订沿用既定细像素格网；终端ASCII字流继续按其独立玩法要求保持字符密度和流动效果。

## 光照、遮挡和交互

日常主光统一左上→右下，先区分背景、可行动地板、角色/物件、提示四层。接触阴影默认偏移1×2逻辑像素，地面暗、物件顶面明，最多三级受光色块。暗色观察保留可走地面与人物轮廓，禁止夜里把肖像脸高亮。晨光先照被子和肩背，脸侧柔和；不以大白三角、全屏雾或发光脸代替空间。

对象按已标定脚点/基线前后遮挡，前景遮罩与物件共用源坐标。能走到后面的墙脸仍是遮挡层，不变成空气墙。墙基、门叶、石岸与桌腿的可见实心边缘对应碰撞；看起来能走的地板必须通过实机脚碰撞检查。互动目标用轮廓、形状和文字共同表达，不只靠色相；朝向永远不作为互动门槛。

## UI、动效与实际显示

UI使用同色板、细像素边线、克制的纸面与墨色层次，图标复用世界物件轮廓。手机仍430×860、场景仍960×540；开场画面铺满可用视口，避免两侧巨大黑边，所有图像等比缩放。《梁祝》完整舞台保留16:9，竖屏提供横屏提示与可用的退出操作，余区使用同色背景。响应式显示可产生非整数屏幕倍率，但素材自身格网不变，采样用nearest；不宣称每台手机上每格都恰好占相同整数屏幕像素。

统一使用项目的“晨札像素 / 755 Morning Note”Regular与Medium字形，24格原生笔画、共用基线，数字等宽；字流继续由小字符组成汉字，采样轮廓来自同一字体库。原创矩阵与开源衍生汉字分别登记，不能把整套中文都称为原创。保留scale-aware绘制，文字局部使用nearest，不能改变图片和世界的过滤。正文目标至少16CSS像素，次要文字至少14，文字对比度至少4.5:1；主要触点目标44CSS像素，绝对最小28。图标可小，热区不能漂离实物。不要绿宝石对勾徽章、默认黑色玻璃大卡片或把答案写在常驻提示上。

角色沿用三向素材与每向8帧、每帧110ms的步行节奏，脚点稳定，摆臂和左右腿相位清楚；不改变连续移动速度来适应绘画格。小动作2–4帧，反应优先于装饰；晨光8–12秒轻微变化。减少动态效果、暂停、失焦和卸载都有静帧；动画完成不能提交剧情、领取物品或启动游戏。

## 骨骼与逐帧协作

角色采用Godot原生`Skeleton2D`/`Bone2D`，参考[官方开源Skeleton2D示例](https://github.com/godotengine/godot-demo-projects/tree/34fc99545fc41520a958248f607101e7d0b95b05/2d/skeleton)的骨链组织；使用本项目原创人物与动作。共同命名为`Hip → Torso → Head`、`Shoulder → Elbow → Wrist → FanSocket`、`Hip → Knee → Foot`。左右翻转围绕脚点进行，整体比例不变，手持物读取真实手腕骨节点的变换，不能在画面上另猜一个漂浮坐标。

《梁祝》首批采用逐帧角色与骨骼道具的混合方式：120×160单格脚点固定在(60,150)，5个原生细像素对应1构图单位；每个姿势的关节表是唯一标定。复杂衣袖轮廓由原创逐帧图保留，附属衣袖骨点幅度硬限±6°，减少动态效果时归零。没有实际绑定Polygon2D权重的部分不称为蒙皮变形，也不拉伸整张角色图模拟关节。见[骨骼标定与来源](../LIANGZHU_ACTOR_RIG.md)。这套脚点、命名、翻转、道具附着与标定记录要求适用于后续角色批次。

## 每批验收与迁移顺序

每批记录输入/输出SHA、工具版本、逻辑尺寸、输出倍率、格网原点、色板、透明度、物件脚点和源图放置范围。先看原尺寸，再看实际桌面和手机显示；格网与色数检查通过不等于构图和玩法验收通过。

先做开场、玩家、一个寝室道具与UI图标的小样对照，再迁移寝室→图书馆/剧场独立对象→湖与教学楼，最后处理校园大底图。大地图需要按原坐标重建，不能批量滤镜后覆盖。道具重绘必须复测清地板、实心边、真实角色脚碰撞、门的开关和感应区；存档、剧情与物品合同不变。

避免：粗细混杂像素、同房间混视角、角色漂脚或比例忽大忽小、把阴影当墙、把装饰层合成实心碰撞、窗框光穿过床栏、整图弹性扭曲、一次性量化全库却宣称全部画风完成、把法线生成当格网修复、直接搬用参考游戏的角色/构图/标识。

参考：[用户给定图鉴的《动物井》](https://dannykkg.github.io/game-art-atlas/#game-813230)用于观察轮廓与局部光源，不能作为本项目斜俯视规则的证据；[Pixel Snapper](https://github.com/Hugo-Dz/spritefusion-pixel-snapper)用于网格/色板清理，[Sprite Normals](https://github.com/Hugo-Dz/spritefusion-sprite-normals)用于独立法线试验。转换不能修复错误透视、比例或碰撞。
