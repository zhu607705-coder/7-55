## P2: deliverable and QA

- A self-contained native Godot project must import, parse, boot, and export using the documented Godot version with no browser/React/Phaser runtime dependency. Documentation must state tested targets and limitations accurately
- Source-native port is not proved by embedding the web app, importing text/content JSON, displaying maps behind buttons, or auto-resolving gameplay actions
- Port critical contract cases to native state/action tests: valid/invalid/repeated requests, phase gates, save/reload, corrupt-save fallback, order independence, terminal invariants. Test simulations through real input and timeline boundaries
- Test final export rather than only editor project. Run boot + representative phone, map, lake, Chapter4 scenes, restart save; then perform continuous start-to-finish native playthrough. Runtime screenshots verify visible feature claims, not just distinct route colors
- Existing `scripts/run-validation-suite.mjs`, `docs/TESTING.md` and specific validators are baseline oracles. Original `npm run validate:release` does **not** prove native parity. The original suite itself disclaims complete playthrough, audio audibility and cross-browser coverage
- Local tested migration commits are authorized. The requested GitHub Draft PR remains pending GitHub write approval; no remote publication, merge or deployment is confirmed.
