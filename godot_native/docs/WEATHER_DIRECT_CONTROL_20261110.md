# 天气小游戏：场景直控试点

本次只修改 Godot 的三层云带小游戏。基线为 `main` 的 `98b9845c5a0ffcdc3885bedf0c643053ee9952e7`。它是 [PR #243](https://github.com/zhu607705-coder/7-55/pull/243) 中小游戏规范的第二个落地点；本分支从 `main` 创建，不依赖 #243 合并，也不复制其盖章改动。

## 玩家路径与边界

```text
雨后返回码头，已取得吹风机
  → 天气页：用吹风机调整云带
  → 三层云带小游戏
      ├─ 返回：关闭本次活动，不上报成功
      └─ 三层均有操作，进入各自目标区并同时稳定 1 秒
           → finished(result)
           → c3_lake.valid_weather 校验
           → 控制器消耗吹风机，解除雨天限制
```

入口、道具消耗和正式存档仍归 [c3_lake.gd](../scripts/chapters/c3_lake.gd) 的 `weather_ready`、`c3_weather_start`、`c3_weather_result`。场景只产生操作与结果；它不直接写章节、背包或存档。

## 改动理由

原 [c3_weather.gd](../scripts/games/c3_weather.gd) 把高、中、低三层的左右控制做成六个常驻按钮，并在默认说明中列出热键。玩家操作的是画面边缘的按钮，而不是正在变化的云带。本次把主操作移到可见云朵，仍让原有风速和控制速度决定实际位移。

桌面键盘作为另一条输入路径保留。返回、开始和帮助属于导航或说明，不承担解谜动作。默认画面只保留必要的状态；详细操作和键盘对应关系放到主动打开的帮助中。

## 不变的玩法合同

以下数值来自 [原天气模型](../../src/modules/QizhenWeatherControlModel.ts) 和当前 Godot 实现。顺序均为低层、中层、高层。

| 项目 | 保留值 |
| --- | --- |
| 初始位置 | `[78, 22, 38]` |
| 目标位置 | `[34, 52, 70]`，每层容差 `±8` |
| 自然风速 | `[5.5, 6.5, 7.5]`，向左 |
| 输入与位移 | 方向为 `-1 / 0 / 1`；速度为 `-WIND + direction × 30` |
| 时间步进 | 单帧最多 `50 ms`；位置限制在 `[2, 98]` |
| 完成条件 | 三层均被主动操作，三层同时对齐累计 `1000 ms`；失去对齐则稳定时间归零 |
| 结果字段 | `moves`、`cloudOffsets`、`controlledBands`、`stableMs`、`elapsedMs` |

拖动不能把位置直接写到目标，也不能在松手后冻结自然风。每层实际施加非零方向才记录操作。章节控制器继续拒绝少于三次操作、缺少任一层操作、未稳定或偏离目标的结果。

## 本次交互与验证

### 玩家实际操作

1. 点“开始调整”，再按住一朵云。向左或向右拖动，给这一层施加风力。云朵按原速度追随手指选定的位置，不会瞬移。
2. 松手后停止施力，自然风继续推动这一层。依次修正三层，画面显示已操作层数和稳定时间。
3. 点“暂停”，再点“操作说明”，才显示详细动作和键盘对照。继续、返回复用已有暂停面板。

| 情况 | 场景处理 |
| --- | --- |
| 第二指或触摸模拟鼠标 | 不能抢走已有云朵；只接受当前拥有者的移动和松手。 |
| 点击空白轨道或只点云朵 | 不自动对齐，不计为已施加风力。 |
| 触摸取消、鼠标丢失按压、拖出活动边界 | 清空输入并暂停，不把取消当成成功操作。 |
| 失焦、隐藏、树暂停、旋转或缩放 | 清空输入并暂停；位置、累计时间和稳定进度冻结。 |
| 明确继续 | 等待新输入；丢弃恢复后的首帧时间，防止后台时间补算。 |
| 返回或完成 | 先结束本局，再发一次信号；旧事件不能再次提交或改成另一终局。 |
| 新实例或显式 setup | 仅重置小游戏局部状态，不创建另一份章节进度。 |

云朵的绘制尺寸与命中区域一起调整，窄屏重排行距，不使用覆盖整行的透明热区。逻辑画布仍为 `960×540`，模型的横向位置不随窗口缩放改变。
