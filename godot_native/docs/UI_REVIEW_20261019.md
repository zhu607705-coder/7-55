# 2026-10-19 发布界面复核

本轮目标是让玩家从正常故事进度继续游戏，正式界面不出现开发检查点、任意章节选择或原型目录。主线与三个独立校园漫游需要在入口上清楚区分。

已通过 computer use 向 [Gemini 网页 Argon 对话](https://gemini.google.com/app/862f03f73afba38f) 提供两张真实 Godot 截图：07:55 微信页、Ctrl+Shift+D 开发面板。首次提问偏向工程实现；用户澄清后已纠正为前端 UI 的布局、按钮命名、视觉层级与章节交接提示。下表仅记录界面意见及项目内取舍，不把模型的示意代码作为实现或测试依据。

| 界面问题 | 本轮处理 |
| --- | --- |
| 主线、独立漫游与原型入口处于同一层级 | 以“主线故事”和“独立校园漫游”分组；主按钮使用“进入主线故事”，避免未有存档时显示已经续玩；保留既有故事入口与三个校园的行为。 |
| 默认灰色按钮容易被理解为不可操作 | 复用项目既有 NativeUi 主题与像素字体，突出主线按钮，保留清楚的焦点、边框及点击范围。 |
| 开发面板暴露章节下拉框和“只看场景”按钮 | 正式环境不创建该入口与原型目录；控制中心保留正常设置及进度管理。 |
| 正式界面显示引擎迁移与内部版本说明 | 使用面向玩家的存档兼容说明。 |
| 海淀漫游混入建筑隐藏、搬移等检查工具 | 正式环境不显示建筑检查入口，正常导览与漫游继续使用既有界面。 |

Gemini 另外提出了顶部任务框微调及章节转场示例。两张静态截图不足以证明正常章节交接缺少转场；示例里的新时间、导语和动作按钮也不是已批准故事内容，因此本轮没有据此改写剧情或推进方式。顶部留白等微调留待实际尺寸与可读性核实。

手机内页继续使用 430×860 的统一框，顶部 40 保留状态栏；横向探索继续使用 960×540 的逻辑画面。正式章节只通过原有剧情和有效存档推进。夜间肖像随环境照明变暗的修复继续保留。

本机另准备了隔离的“发布行为试玩”工程，通过 Godot 项目管理器实际导入、运行；它使用编辑器二进制，明确不是导出的 release binary。生产特征、入口拒绝与存档续接分别由真实 PCK 和该隔离工程核实，详细证据见 `PUSH_ACCEPTANCE_20261019.md` 及相应 verification 记录。
