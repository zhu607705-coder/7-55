# 启动校验优化 · 2026-10-24

本轮缩短首次加载与缓存重进的校验等待，并修复实测发现的横向剧情场景字幕遮挡工具栏。改动限于浏览器校验、字幕布局及相应验证；章节控制器、缓存身份和存档协议保持原义。

## 实施

`web/content_loader.js` 的每个 64 字节压缩块原先通过解构读取状态，再创建数组和回调写回。一次 39,513,091 字节的引擎校验会执行约 61.7 万次这种循环。现在直接读取和累加八个标量，保留逐块校验、完整资源校验、1 MiB 主线程让出、取消、重试与损坏缓存修复。

`tools/profile_web_loading.mjs` 增加 `--cpu-rate=1..20`，把 CPU 模拟倍率写进报告；报告明确区分访问地址、网络模拟与实体设备，避免把线上 URL 测量误写成本地 HTTP。

复核手机截图时还发现：物品栏已移入画面，剧情字幕却把其位置当成画面外的阻挡区域，导致横向场景在竖屏回退时把字幕挤回工具栏。`c3_narrative_host.gd` 现在只扣除真正进入下方空白区的控件；没有空白区时，字幕遵循实际工具栏上方的安全范围。原有镜头、路线、字幕内容与剧情计时保持不变。

## 测量方法

- 基线源码：`6022a6b090d491eb85c97e09335736dc1ec11759`。
- 候选构建：同一提交加本轮加载器修改，`sourceDirty: true`；Godot `4.7.1.stable.official`。
- 候选 source-input：`0090f1bd94e7df1f029d1b7a8c15b6a68aeca9282859f1eff3016f25515abd59`。
- 浏览器 A/B 使用同一份导出 PCK、WASM 和其余资源；旧版本端点仅替换加载器响应为基线字节。这个受控端点用于性能对照，不是可以发布的完整基线制品。
- Chrome、390×844、DPR3、20 Mbps、60 ms 延迟；每种 CPU 倍率做三次旧/新交替对照。每次先用新隔离配置冷启动，再关闭并用相同配置重启浏览器，检查缓存重进。
- `ready` 指资源校验和引擎准备完成、出现“进入游戏”；与用户点击后进入 Godot 主界面的 `main` 时间分开。没有把下载条到 100% 当作运行完成。
- Node 微基准使用实际导出字节和独立 Node SHA-256 校对，但 IDB 与网络是内存模拟；它只支持校验开销结论，不能替代浏览器或手机测量。

最终含字幕修正的候选 source-input：`74776bd70ba34707368e314027d2e1459a3452cf0bb92b797a4d0539f1d6bdbb`。下列 A/B 数据专门隔离加载器改动；字幕修正随后在最终导出上验收，没有将前后不同制品混作性能对照。

## 浏览器结果

三次对照的中位数，单位秒：

| CPU 模拟 | 加载方式 | 旧版 ready | 新版 ready | 缩短 |
| --- | --- | ---: | ---: | ---: |
| 1× | 首次 | 14.358 | 14.046 | 0.312（2.2%） |
| 1× | 缓存重进 | 1.150 | 0.729 | 0.421（36.6%） |
| 4× 慢速 | 首次 | 15.969 | 14.452 | 1.517（9.5%） |
| 4× 慢速 | 缓存重进 | 2.970 | 1.412 | 1.558（52.5%） |

12 次独立浏览器运行、24 次冷/热加载均进入实际 Godot 手机主页，没有页面或运行时错误。所有缓存重进都没有请求启动资源块。每次主页观察 1.5 s，rAF p95 均不超过 16.8 ms；这些短样本仅作回归信号，不代表整场游戏的帧率验收。

1× 缓存重进至 Godot 主界面的中位数为 3.288 → 2.866 s；4× 为 8.854 → 7.284 s。此指标包含测试器点击与入口等待，不能把 ready 的百分比套到完整进入流程。

本机线上基线与本机 A/B 服务不直接作百分比比较。候选的源码输入与线上版本仅有加载器和两个平台转换生成的 OGV 字节不同；A/B 两端使用完全相同的候选媒体、PCK 与 WASM。

## 回归验收

- 资源缓存 45 项、加载器 50 项、启动表现 44 项、压缩服务 49 项检查通过，保留错误校验、取消、断点恢复和低能力环境回退。
- 相关原生对话回归 7 项通过；新增真实剧情字幕与工具栏的几何回归，在 390×844、430×860、844×390、1280×720 和 1.0/1.4 字号下验证。该剧情壳共 85 个断言通过。
- 原生启动、资源解析、隔离存档、旋转提示、启动表现 5 项检查通过；最终包重新运行 source sync、完整媒体转换校验、资源导入与正式导出。
- 加载器阶段的真实网页手机输入验收 887 项通过，包含点按、摇杆、旋转中断、取消、实际导入与恢复。
- 保留 Web 的 quick 5 项与 release 38 项通过。最初完整检查因临时镜像链接、未提供 ffmpeg/ffprobe 与 workflow 上下文而失败；修正隔离环境后全套通过，没有为此改产品代码。
- 新浏览器字幕回归在旧导出上稳定失败于“approach caption clears the visible footer”，证明检查可识别本次问题。最终导出在 Chrome 手机模拟（390×844、DPR3）通过 939 项，桌面 1280×720 通过 937 项；新断言验证字幕与可见工具栏分离，手机字幕进入下方空白区。两份报告均无页面/运行时错误，实际截图已复核。

## 发现与限制

线上基线在本机限速、手机尺寸模拟下：冷启动 ready 21.381 s、主界面 23.455 s；缓存重进 ready 1.874 s、主界面 4.007 s。主页的两段 15 s 观察没有超过 50 ms 的浏览器帧间隔。用户点击后的界面构建仍有约 700 ms 的长任务，本轮校验优化不代表已经消除该阶段的停顿。

原生视口实验确认隐藏世界已由 SubViewportContainer 停止绘制，手动改更新模式没有收益，因此未纳入代码。原生启动分段计时只作定位：它使用调试引擎，不能作为正式网页或手机的速度承诺。

浏览器 CPU 模拟并不代表某款实体手机；rAF 是浏览器调度而非 GPU 逐帧耗时。实体 iOS/Android 与 Safari/Firefox 性能仍需分别验证。

原始证据保存在本机 `~/Library/Application Support/755-tools/verification/runtime-upgrade-20261024/`。测试使用独立存档与浏览器配置，不读取或覆盖玩家实际存档。
