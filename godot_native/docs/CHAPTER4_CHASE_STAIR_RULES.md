# 恢复原追赶楼梯的会话与平台规则

原生版此前只在活动内部记录平台，普通重载会回到入口；它还使用固定两秒保安延迟、更小的玩家脚框，以及立即本地重试。此修复按原 Web 源码恢复这些行为，继续使用原楼梯图、方向帧、导航图和移动速度。

## 来源与行为

| 行为 | 原源码 | 原生实现 |
| --- | --- | --- |
| 平台保存、合法失败和楼层变化 | `ChapterFourTemporalMazeController.ts` | `chapter4.gd` 保存连续平台；被抓后仍按原规则清零平台并返回 A1 大厅 |
| 普通重载进入对应楼梯 | `RpgGameHost.tsx` / `SaveStore.ts` | Main 在启动或明确返回现场时创建唯一活动；刷新、缩放不自动重开已退出活动 |
| 保安先后距离 | `ChapterFourChaseStairwellScene.ts` | 同次尝试的临时距离传入；入口限定 650–2000，普通重载使用 650；延迟由原 174 单位/秒计算 |
| 完整碰撞脚框 | `PlayerMetrics` / 原楼梯可行走矩形补集 | 使用 19.5×14.625 玩家脚框；保安脚框与原导航算法保留 |
| 被抓演出 | `ChapterFourGuardPresentation.ts` | 原台词、5.2 秒冻结和一次失败回调；关闭或替换会话取消旧回调 |
| 出口保安距离 | `ChapterFourChaseStairwellScene.ts` | 原路径距离加未消耗延迟传入 A2，范围 600–2000；未新增持久化字段 |

普通平台重载与失败重试不同。到达平台后正常关闭，可以从该平台的原出生点继续；被抓仍返回原 A1 失败点，不获得免费平台复活。

## 进度与输入归属

活动只能请求进度。控制器验证当前会话、尝试号、场景、楼层、连续平台、时间、位移、完整脚框与已接受路径前缀，之后才保存平台。最终出口仍验证累计轨迹。重载创建新令牌，旧活动不能提交平台、失败或完成。

短的合法重载路线可以少于旧版固定的十个采样点；空轨迹、传送、不合法步时、非有限数值、越界、跳平台及旧令牌仍被拒绝。失败和出口的位置在保存前写入既有位置表，避免稍后的刷新恢复旧大厅位置。

保持 208/174 移速、原可走区域、原路线和合法失败。没有为自动操作调整难度。刻意退出保留现有返回交互，恢复必须由正常启动、明确返回现场或原主楼梯交互触发。

## 验证边界

旧版的四个差异先由受控负例复现。候选规则检查 70 项，楼梯呈现 119 项；章节链 117、保安 17、保安演出 64、设备/Main 38、模态输入 7 项受影响检查通过。合计 432 项为针对性检查，不是完整发布验收。受控路径与捕获测试不算手动通关。

2026-10-05 实际 390×844 操作从未改动的已获得楼梯入口存档出发，正常按键到第一平台，明确返回后自动保存为平台 1，尝试号保持 60，正常退出。路线使用源码知识和返回辅助；此前的 60 次计数包含无人操作入场，不能表述为 60 次实际失败。此段使用 Dummy 音频，没有听觉验收。

同一平台存档已普通重载：实际画面保留平台 1，正常方向键通过平台 2 和出口，A2 自动保存保持 attempt=60。随后 Tasks 显示“追进 202，关好门”；202 尚未进入。

独立的同平台副本由只读观察器载入普通 Main，自然接触触发原保安台词；51 个采样中双方位置冻结，次数维持 60。楼梯活动退休时，控制器回到 A1 大厅 (590,612)，清零平台并设 pending，次数只加至 61。后续无人操作的大世界入场到 64 另记，不能算四次玩家失败。最后活动采样为 5150.176ms，下一观察已退休；没有精确 5200ms 的实际完成时刻证据。该边界由自动化 5199/5200 检查补充。普通入口与观察器启动时机有区别，前者的重载已单独验证。

尚无新打包检查、全套回归或触屏硬件验收。独立观察器仅用于本地证据，不进入生产补丁。

另有继承的低帧率边界：原场景把追赶 elapsed 的单次增量上限设为 100ms，通用原生活动目前仍沿用 50ms 模拟步长上限。本段未扩大到通用时序修复，也未据此声称所有帧率下的完整时序等价。
