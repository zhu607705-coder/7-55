# Godot 跨章节小游戏盘点与改造顺序

审计基线：`zhu607705-coder/7-55` 的 `main`，提交 [`98b9845c5a0ffcdc3885bedf0c643053ee9952e7`](https://github.com/zhu607705-coder/7-55/commit/98b9845c5a0ffcdc3885bedf0c643053ee9952e7)。以下是静态源码盘点，不是所有章节的试玩验收。范围是正式 Godot 章节中的独立活动及相邻设备界面。

正式入口由 [`main.gd` 的 `_open_game_now`](../scripts/main.gd) 承接。该宿主已经负责独占活动、结束回调、取消和返回焦点。无需再造小游戏运行时。需要修改的是各活动没有对齐的返回、物件操作、信息量和窄屏体验。

规范见 [Godot 独立小游戏设计规范 v1](MINIGAME_DESIGN_STANDARD.md)。

## 不应混进这次统一改造的内容

- 第三章配饮机、道具箱、鱼竿组装和第四章时钟、电源、电梯等已有物件近景。它们可采用同一输入/返回规则，但不能为了统一而从世界关系中拆走。
- 第三章划船与天鹅追逐现由 `c3_lake_world_session.gd` 等世界会话承接。`minigame_host.gd` 中还有 `kayak` 模式，但本次检查到的 `c3_lake.gd` 正式入口没有请求该模式。因此不能把这个遗留分支当作当前独立活动再改一遍。
- 第3.5章主要是手机调查、录音和证据整理，本次没有从已查章节入口确认独立 `game`。不要凭章节号新增小游戏。
- 第四章开场、星灯结尾也挂在活动宿主下，但属于演出交接，不按小游戏数量统计。
- 未来学习中心有自己的可选活动和关卡库，先保持现有独立范围。本次规范不等于已审完或重做那一整套关卡。

## 改造顺序与可验证交付

### 第一批：先修完整路径

本批补图书馆盖章的返回路径，并建立规范。通过扫描前、扫描后、盖章动画中取消、重复取消、重新进入、正常完成等检查，证明返回不会偷偷完成任务。保留扫描规则和原有画面，不顺便改剧情。

同类后续检查是追光演出中暂离的语义、其他活动的焦点恢复和退出后的回调。这里需要从实际章节入口验证，不能只检查是否声明了 `cancelled`。

### 第二批：以一项活动验证物件直控

优先天气三层云带，因为问题范围小、现有目标明确。候选方案是直接拖动云带或拨动每层风向杆；动作仍进入现有方向/速度模型。比较修改前后完成率、误操作、失败原因和双指行为。未完成该验收前，不批量改骑行、楼梯和所有设备。

随后逐个处理骑行的操作负担、楼梯的实体机关和网格转运的空间可读性。每批保留现有完成条件，并提供一次正常完成、一次失败恢复和一次退出重入的证据。

### 第三批：再评估 LDtk

优先选 `progressive-transport-levels.json` 中一个小关卡。现有数据已经有 `rows`、`actor`、`objects`、`plates`、`gates`、`targets`、`checkpoints` 和 `exit`，适合做地图/实体编辑。先证明导出转换不改规则，再决定是否扩大使用。

本批没有新增 LDtk 插件、`.ldtk` 文件或运行时依赖。印章、手机、天气控制 UI、钓鱼节奏和3D楼梯不强套 LDtk。

## 本批实现与首轮检查

本批只修改 `identity_stamp.gd` 的返回导航与取消生命周期，并增加 `test_library_stamp_return.gd`。返回在扫描、待盖章和盖章动画中均可用。取消关闭本局且不发送 `finished`；正常成功仍使用原证明。短横屏把返回导航放在画面空闲边缘，保留可点击的显示尺寸，而不压缩或重排纸张。

- Godot **4.6.3** 隔离工程：新增返回/输入回归 **71项通过**。覆盖鼠标、模拟触摸取消、多指、移出释放、失焦、重复取消、延迟帧、正常完成，以及390×844、844×390、1280×720、1152×760和旋转后的导航尺寸。
- 原 `test_library_stamp_paper.gd` 中的独立盖章部分：**58项通过**。这不是原脚本的完整Main集成验收。
- 文档的24个相对链接已按基线Git树及新增文件检查，路径有效；源码入口经过独立复核。
- 隔离工程使用当前脚本、印章PNG、纸张数据和MorningNote字体。源备用Fusion字体未能在该工程中取得，临时使用MorningNote代替；仓库字体未改。因此这次结果不证明正式字体的渲染与排版。
- 首轮未执行：Godot4.7.1正式验证、完整Main返回/重入及存档链、真实GodotWeb、截图验收、实体手机。后续原生验证见下节；无头测试仍不能替代画面验收。
- 已知保留状态：取消后控制器的 `lostFoundStage` 仍是 `scanning`。源码中再次 `lib_scan` 不受此字段阻止，报告目标也仍可用；但前台询问可能继续显示“正在核对”。本批未扩展共享取消协议。首轮隔离工程仅检查新实例重入，后续已补实际Main与重载验证。

本批结果可作为Draft PR的候选证据，不表示整个小游戏规范已在全部章节落实，也不表示已达到合并或发布条件。
