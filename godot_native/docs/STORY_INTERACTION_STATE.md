# 7:55 主线关节点与交互状态

正式入口从 `entry.tscn` 进入 `Main`。手机、场景物件和小游戏将动作交给 `State`，由 `ChapterSystem` 调用各章控制器。表中的动作和字段来自当前 Godot 实现。一个章节可以同时保留多个已获得的事实，例如 022 的四份证据和启真湖的独立材料分支。

## 主线交接

| 关节点 | 进入条件与完成动作 | 保存与恢复 |
| --- | --- | --- |
| 第一章 · 闹钟、手机线索、签到 | 校园网和有效签到码通过 `c1_checkin`，进入旁白拦截。三次有效拦截、锁定、交涉和白场由 `c1_intervention_result` 校验后进入第二章。 | 保存已取得的数字、道具和签到结果。签到完成但尚未通过拦截时，继续入口回到 `ending`，可用 `c1_resume_ending` 重新开启。 |
| 第二章 · 系统对话、宿舍、身份和移动 | `actOne.phase` 从好友消息进入系统、取卡和移动任务。体艺更新、锻炼、雨滴、身份及 CC98 等分支分别保留事实。完成真实移动和预约后，`c2_dorm_exit` 解锁图书馆路线。 | 存校园卡、身份、更新阶段、体艺和移动事实、预约结果。下载表现和当前按键可重新开始。已有更新完成状态从 `tiyiUpdateStage` 恢复。 |
| 第二章 · 基础馆 022 | `lib_enter` 进入基础馆。入馆记录、馆藏规则、身份和现场证据进入上传与 BD 流程，取得 PASS、移走书包再坐下。由 `lib_story_complete` 和 `lib_opening_complete` 承接正式对话及食堂入口。 | `ui.libraryFinalsPhase` 与 `ui.libraryFinalsPuzzle` 记录证据、阅读确认、申请和座位事实。抽书、扫描、打印和站位表现分别由当前场景维护。已取得未读的规则仍可继续阅读。 |
| 第三章 · 食堂与骑行 | 寻找纸条，依次通过托盘、饮料、点餐、取餐和拦截。合格的 `c3_defense_result` 提交纸条逃逸交接，清锁与支付后开启骑行，`c3_chase_result` 接收合格的骑行证明。 | `canteenHunt`、钱包和持有物记在正式档里。待播的逃逸段保存 `native.c3_pending_handoff`。重进可恢复演出和已支付的骑行阶段。 |
| 第三章 · 剧场与出口 | 退票、半票、验票、节目、道具箱、追光与纸条反转由 `theaterHunt` 控制。完成反转后，空格或触控在实景出口发起走门。角色越过门槛才提交 `c3_target:theater_exit`，进入 `campus_theater_junction`。 | 验票接续和道具箱可恢复。开门进度、走门时钟和按住输入只在当前场景有效。走门中断可在剧场重试，已提交的出口从启真湖路段接续。 |
| 第三章 · 启真湖定位和装备 | 三个独立来源通过 `c3_map_confirm` 确认地点。码头装备和安全警告后可触发落水救援。吹风机清雨后回湖，用实际交替划桨完成教程。 | `qizhenLake` 保存证据、装备、救援结果、天气条件、区域、载具和 `safeSpawnId`。救援演出的时钟和划桨输入由当前运行实例维护。 |
| 第三章 · 钓鱼、装配和追逐 | 钓取钥匙、网框和围栏支线分别解锁材料。控制器校验当次抛竿结果和装配材料。捕获纸条后进入黑天鹅追逐，实际到达安全点才结束。 | 单次抛竿仅绑定当时的存档、阶段和目标。已钓获物、物品消耗和追逐安全点保存。旧档已用抄网的材料收据和旧鲫鱼交换仍可接续。翻船或被追上按当前湖区检查点恢复。 |
| 第 3.5 章 · 记录恢复 | 调查分支以 `native.c35_investigation.step` 管理作业、照片、群聊与私信、地图、入口、录音和网络记录。证据支持位置和时间结论后才允许恢复回放。旧存档的记录恢复继续走既有入口。 | 保存已交附件、证据、地图标记和核对结果。回放由 `chapterThreeInterlude` 的已解锁阶段签发，北教开场结束才由 `c4_prologue_end` 提交跨章。 |
| 第四章 · 北教旧钟、电梯、错位楼梯与 204 | 纸条和旧钟启动调查。时针装回后，经电梯线索与楼层校准前往 A3，错位楼梯证明通向 A2。204 的参考、残留和摆放由控制器核对，定位片装回旧钟后进入检修。 | `chapter4.phase`、楼层、时间态、房间、证据和谜题检查点持久化。电梯动画、楼梯当前输入和未完成的拖放可重试。 |
| 第四章 · 断电、保安、202 和结尾 | 配电、路线证据和楼梯的逐层证明决定追逐走向。`c4_chase_failed` 处理本次被捕，`c4_chase_done` 校验真实路径后进入 A2。回收最后一分钟后回旧钟，完成双凭据签到和灯的确认才结局。 | 保存追逐编号、已确认平台和对应楼层安全点。失败只回退本次追逐。已签收的分钟、签到证据和结尾确认可继续。 |

## 状态由谁维护

- 章节控制器维护物品、消耗、余额、剧情阶段和证据；场景保留相机、姿态、焦点、按住键和当前演出的时钟。
- 有跨场景意义的中间结果写入剧情收据或检查点。换档或刷新时，由已保存的事实重新签发所需交互。跨湖区的入口姿态只由触发该次过渡的运行状态使用，续档回到存档记录的安全位置。
- 重复提交时，已完成的门槛保持已完成。具备临时会话的交互在校验结果前核对会话和当前场景条件。退出钓鱼或隐藏浏览器标签时回收当前会话，迟到结果不会干扰重开的一竿。旧档的救援演出也不能占用新档的救援入口。
- 导入由 `State` 先校验候选存档和附件，成功写盘后通知场景重建。写入失败时恢复原来的状态实例，使依赖该实例的现有交互能够继续。普通自动存档和便携导出都从副本移除 Control Center、背包展开和选中物品等临时界面状态。
