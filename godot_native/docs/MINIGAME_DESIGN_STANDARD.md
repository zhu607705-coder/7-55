# Godot 独立小游戏设计规范 v1

适用于 `godot_native/` 正式章节中的独立活动，以及从世界物件进入的局部操作界面。引擎与 Web 模板继续使用项目要求的 **Godot 4.7.1**。本规范不另建引擎、小游戏大厅、存档或剧情控制器。

设计依据是现有的[架构边界](../../docs/ARCHITECTURE.md)、[物件优先与发现式解谜规则](../../AGENTS.md#object-first-gameplay-interaction-user-design-principle-2026-10-29)。本规范把这些规则变成每次修改可以检查的项目。已有章节的明确演出要求优先，例如开场字流不恢复常驻标题、教程和失败面板。

当前盘点、源码依据和迁移建议见[跨章节审计](MINIGAME_AUDIT_20261110.md)。审计中的建议不表示这些改造已经实现。

## 1. 先确定界面职责

| 类型 | 玩家主要做什么 | 界面与进度边界 |
| --- | --- | --- |
| 独立实时活动 | 移动、拦截、控线、避障 | 进入后独占输入；暂停冻结判定；终局由章节控制器验证。 |
| 空间推理活动 | 推物件、改通路、调整机关 | 物件和可达空间是主画面；撤回与重来只改本局。 |
| 设备近景 | 盖章、转盘、接线、调灯 | 在能看懂的物件上操作；保留返回原现场的路径，不强制改成满屏菜单。 |
| 可选观察或练习 | 看关系、试参数、重复实验 | 不新增剧情门槛，不因退出、失败或阅读顺序消耗道具。 |
| 过场与结尾 | 看演出、回答已授权的问题 | 不因为挂在活动宿主下就套用分数、失败、重试和通关奖励。 |

同一章节可以用不同构图。统一的是输入、恢复、验证和反馈规则，不是把所有画面做成同一张控制台。

## 2. 每个活动先写一张设计卡

修改现有活动时，在 PR 或对应设计文档填写下列项目。没有证据的项写“待验证”，不要用设计愿望替代现状。

| 项目 | 必须回答 |
| --- | --- |
| 身份 | 活动 ID、章节、正式入口动作、脚本路径，是否可选。 |
| 当前问题 | 玩家现在要解决的一个具体问题。不要提前给出完整答案。 |
| 主要操作 | 玩家直接操作哪个物件；按下、移动、松开分别做什么。 |
| 规则证据 | 玩家从哪里看出规律；第一次试错能排除哪种解释。 |
| 完成判定 | 哪个模型判断完成；章节控制器验证什么；奖励与道具如何变更。 |
| 失败与恢复 | 失败原因、保留内容、局部重试点、撤回范围。 |
| 离开与重入 | 返回哪里；哪些状态保存；哪些本局状态清空。 |
| 输入与视口 | 鼠标、触摸、键盘等价路径；最窄屏幕；旋转、缩放、失焦处理。 |
| 验收 | 对应测试、普通入口复现步骤、真实 Godot 画面，以及尚未执行的检查。 |

## 3. 玩法：让玩家建立并验证关系

空间与装置谜题采用以下学习顺序，但不强制玩家按固定顺序查看线索：

```text
看见差异 → 提出猜想 → 操作物件 → 看见结果 → 在变化后的情形中应用
                 ↑                 │
                 └──── 修正猜想 ────┘
```

- 第一段只引入一个关键关系。玩家可以安全试错，并看见动作造成的变化。
- 第二段改变位置、条件或物件，检验玩家是否理解同一个关系。
- 后续段可以耦合已有约束。不得用多点几次、重复读完、等待计时或更小的热点冒充推理深度。
- 实时活动则先让玩家看见危险，再要求动作。危险预告、碰撞体、控制响应和反馈必须一致。时序、容差和速度的变更要单独验证，不能隐藏在 UI 改动里。
- 保留合法的不同解法。不增加“必须先看某张提示”的门槛，除非该证据本来就是章节控制器规定的事实。
- 辅助降低操作负担，不直接写入通关。不要在失败若干次后自动授予完成证明。

## 4. UI：场景是主界面

### 默认画面

1. 主区域显示物件、角色和它们的关系。必要的目标与本局进度保持简短。
2. 返回、暂停、重来等导航可用原生 `Control`。它们不能遮住关键物件。
3. 操作说明和键盘对照放在主动打开的帮助中。首次必要提示应短暂出现，并可关闭。
4. 全局下一任务仍由共享任务栏负责。活动只说当前操作、当前结果和如何纠正这次失败。

### 物件操作

- 灯、扇、印章、旋钮、云带等优先直接拖动、旋转、按压或拨动。可见物件、实际命中区和运动轨迹必须相符。
- 移动优先复用现有可辨认摇杆和点地接近。不要再造一个行为不同的方向盘。
- 不显示辅助命中框。必要的扩大触区必须跟随物件，并且不能覆盖相邻控件。
- 键盘仍是可选等价输入。默认标题和主按钮不应靠 `A/D`、`Space` 等按键说明才能被理解。

### 尺寸与可读性

- 手机宿主保留现有 430×860 逻辑框与顶部 40px。活动收到的 430×820 内容区不应再预留第二条状态栏。
- 世界玩法保留已有空间坐标、相机与比例。响应式宿主可重排边缘 UI，但不能把模型坐标随窗口伸缩。
- 检查最终屏幕尺寸，不只检查逻辑尺寸。新增主要导航和频繁触控目标以 **至少 44×44 显示像素**为验收目标；优先达到 48×48。现有较小控件按影响逐步整改，不扩大为整屏透明按钮。
- 文字必须能在窄屏读完。短横屏可把工具放到空闲侧边；需要滚动的说明用原生滚动容器。不要缩小整张游戏画面来塞进更多文字。
- 状态不能只靠颜色表达。错误还要说明是哪类不匹配；成功用符合场景的文字、墨印、光或动作，不添加与项目风格冲突的通用徽章。

## 5. 输入与生命周期

```text
进入 → 准备/直接操作 → 进行中 → 提交证明 → 章节接受 → 返回/交接
                         │          └→ 拒绝：保留可恢复状态
                         ├→ 暂停 → 明确继续
                         ├→ 失败 → 局部重试
                         └→ 取消 → 清理输入与本局任务 → 原现场
```

上图是验收状态，不要求引入一套新的基础类。优先复用现有 `main.gd`、`native_pause_overlay.gd`、活动宿主及各自模型。

- 一个接触只能归一个操作对象。第二根手指不能偷走第一根手指的拖动；触摸模拟出的鼠标事件不能再次执行同一动作。
- 区分正常松手和取消。正常松手可以抛竿、落下物件或完成按压；系统取消不得变成一次成功操作。
- 松手、取消、失焦、隐藏、打开遮挡层、旋转、重试和退出都要清理持有输入。取消拖动不能留下移动、蓄力、冲刺或重复点击。
- 触摸按钮要检查释放点；按下后移到按钮外再松手，不得激活。物件拖动则按自身规则回位或保留最后有效位置。
- 时间敏感活动失焦时暂停，返回后等待明确继续。恢复帧不得把后台经过的时间一次性补入游戏。
- 退出必须可达。除剧情已明确锁定的短交接外，正在扫描、准备、操作、失败时都能回到来源界面。
- 取消与完成互斥且至多发出一次。退出后的计时器、动画、异步回调不得再发成功证明。
- 本局“重来”不得重置章节、背包、钱包或正式存档。需要清除长时间本局进度时，先说明丢失范围；一个可撤回的小动作不必弹确认。

## 6. 模型与剧情只有一个权威

```text
原生物件/Control ──意图──> 活动模型 ──过程证明──> 章节控制器
       ↑                    │                      │
       └────── 可读状态 ─────┘                验证后写 State/存档
```

- 展示层不直接授予物品、改章节、扣费或写通关事实。音频与动画完成也不等于成功。
- 已使用输入回放、会话标识和布局摘要的活动必须保留这些验证。不能用 `won=true` 或客户端最终坐标替代过程证明。
- 取消不提交成功证明。重入使用当前章节条件；旧会话的延迟结果不能影响新活动。
- 可选活动继续保持无剧情奖励。不要为了统一“结算页”给几何阅读或码头练习添加存档事实。
- 现有轻量证明若要升级，另开明确任务，覆盖存档与控制器回归。本规范不静默修改全部旧契约。
- 先提取已重复且行为一致的小部件。不要为了文档统一而重写所有活动、增加另一份注册表权威，或把不同玩法塞进一个巨型父类。

## 7. 提示与反馈

| 场景 | 告诉玩家什么 | 不应该做什么 |
| --- | --- | --- |
| 无效操作 | 这次动作为什么无效，下一次可以比较什么 | 只播放音效、无声返回，或直接点亮正确答案 |
| 一般失败 | 本轮失败原因、已经保留的内容、重试入口 | 清空不相关章节进度，反复播放长前奏 |
| 主动求助 | 先指出不匹配类别，再建议比较，最后指回证据载体 | 仅按失败次数自动显示完整参数与路线 |
| 成功 | 控制器已接受的结果和当前物件变化 | 在验证之前显示“已获得”，重复发奖励 |
| 资源失败 | 这次界面没有完成加载，可以返回或重试，剧情未变 | 假装成功，或停在没有返回入口的空白页 |

## 8. LDtk 只用于适合的空间编辑

LDtk 是二维关卡与实体编辑器，不是 Godot UI 库。当前仓库没有 `.ldtk` 资源；本批不增加 importer、运行时依赖或数据转换链。

| 范围 | 结论 |
| --- | --- |
| `progressive-transport-levels.json` 的格子、墙、水、出生点、机关位置 | 最适合作为后续单关试点。Godot 模型仍负责推行、开门、检查点和完成判定。 |
| 2D 房间中的障碍与触发区 | 可在坐标、实体 ID 和现有碰撞完全一致后评估。不能顺便重画正式世界地图。 |
| 表单、手机页面、印章报告、帮助、结算、暂停 | 用 Godot 原生 UI，不放进 LDtk。 |
| 钓鱼节奏表、字流语义、扇影投影、3D 错位楼梯 | 不适合用二维网格替代，保留已有规则与几何模型。 |

试点步骤：

1. 选一个非关键空间关卡，保留原数据与固定解法回放作为对照。
2. 优先评估 [Super Simple Export](https://ldtk.io/docs/game-dev/super-simple-export/) 的分层 PNG、`data.json` 与 IntGrid CSV。转换必须离线、确定性、可校验；只把已有模型所需字段送入 Godot。
3. 检查实体稳定 ID、尺寸、坐标原点、图层顺序、碰撞和检查点。布局摘要变更必须使旧会话失效。
4. 用同一组有效/无效动作回放证明行为等价，然后再考虑扩展。
5. 若改用社区 importer，先锁版本并验证 Godot 4.7.1。已有[分离关卡 `layerInstances == null` 问题](https://github.com/heygleeson/godot-ldtk-importer/issues/65)需要专项检查；单个已知问题不等于所有版本都不兼容。

## 9. 每个 PR 的验收清单

- [ ] 从正式章节入口进入，而不只从脚本预览进入。
- [ ] 鼠标和普通触摸均能完成主要操作，无需键盘补步骤。
- [ ] 键盘等价路径有效，焦点不会被隐藏按钮截走。
- [ ] 覆盖按下后移出、取消、多指、模拟鼠标、失焦和旋转。
- [ ] 覆盖准备时退出、操作时退出、失败重试、再次进入和成功交接。
- [ ] 取消后的延迟帧不完成、不扣道具；正常成功只提交一次。
- [ ] 章节控制器拒绝无效结果；道具消耗、奖励和存档仍符合原契约。
- [ ] 已有暂停、减少动态效果、静音与资源失败路径没有退化。
- [ ] 检查 1280×720、一个非 16:9 桌面、390×844、844×390。测量显示像素中的触区和文字。
- [ ] 对 UI 变更检查真实 Godot 画面。原生无头测试、真实 Godot Web、浏览器模拟触摸、实体手机分别记录，不能互相替代。
- [ ] 执行受影响专项与项目要求的验证。记录引擎版本、提交 SHA、通过/失败/未执行；聚焦通过不能写成全量通过。
- [ ] 工作分支和 Draft PR 及时保留已完成的一小批。未经额外授权不合并或部署；远端提交与 CI 状态分开报告。

## 10. 首批设计卡：图书馆盖章

- 身份：`identity_stamp`，第二章 `lib_scan` → `identity_stamp.gd`，主线材料核验。
- 当前问题：报告已完成扫描，玩家给书包盖“非本人”印章。
- 已有规则：扫描至少 720ms；三个身份检查均不通过；实际盖章后发出证明，由 `library022.gd` 的 `lib_scan_result` 接受。
- 本批变化：补安全返回与键盘等价路径。退出不发成功、不消耗报告、不发证明；再次从前台进入可以重新操作。
- 保留：扫描数值、盖章动画、减少动态效果分支、物品 ID、章节接受条件、原纸张与印章素材。
- 后续建议：把盖章主操作从文本按钮逐步迁移到可按压的印章本体。先验证触区、按压/取消和印章接触轨迹，再替换现有输入。该建议未在首批实现。
