## 碰撞和输入边界

校园脚框为 16 × 10 世界像素，中心为角色锚点加 `(0, 36.5625)`。碰撞、地面点击、路标、路径规划和校园遮挡共用这个脚底中心。图书馆使用自己 36 × 10 的脚框和既有路线预算。场景的脚框参数见 `scripts/player_metrics.gd`。

支持掩码只补充逐处复核的承重区域。实体、水面、剧情门槛和门扇碰撞仍然优先。成章楼后铺地、基础图书馆门前与西侧、中央南部花坛、西教南侧和银泉岸边铺地有独立支持掩码。花坛边框和楼体落地面负责碰撞，树冠、屋顶裁片按各自脚点遮挡角色。

主路优先用最早 Web 的 `CampusPathGrid` 算法。用当前北向图的源通行掩码合成 24 像素保守格，按原邻居顺序和代价搜索，再沿原格网检查可直达点。Godot 逐段扫掠当前脚框，检测实体和水面。新增铺地、窄通道及受当前碰撞影响的路段使用作者源生成的 4 像素格网。搜索可绕出当前画面，最终保留精确点击落点。

校园已规划的落点和途经点用源坐标保存。滚轮、相机拖动、双指、视口重排重新投影；失焦暂停走动，重新聚焦恢复。地图底部由实际按钮和可见对白框处理命中。平滑六份已开放路径的源掩码，并在键盘碰边时尝试安全的切向步幅。所有步幅仍检查完整脚框、水域、实体和交互门。

## 复现和验证

使用仓库固定的 Godot 4.7.1 与同版 Web 模板，安装根目录锁定的 Node 依赖，以及 Python 的 Pillow、NumPy。按原生 README 先执行源同步和媒体准备，再运行：

```sh
python3 godot_native/tools/build_campus_layered_map.py
GODOT_BIN=/absolute/path/to/Godot_4.7.1 node godot_native/tools/validate_native.mjs --profile full
npm run validate:release
```

校园回归覆盖分层纹理身份、真实水面、遮挡顺序、完整脚框、精确路径边界、支持区替换及原生点击行走。`test_campus_v12_connections.gd` 默认运行成悦样本；四个 `test_campus_v12_*` 包装测试分别运行南门、东岸、西园及既有区域回归，均会被原生测试入口自动收集。专项诊断仍可设置 `CAMPUS_V12_FIXTURE` 和绝对路径 `CAMPUS_V12_REPORT`。旧脚框测试已经迁移；历史旧版连接样本不作为当前自动验收。

正式 Godot Web 导出、实际浏览器普通入口与移动设备验收分别留证。原生专项、字节身份及导出通过不能替代这些验收，也不能推导为整张校园碰撞已全部校准。具体执行结果和未通过项见本次 PR 说明，不沿用历史试玩测试结果作为当前结果。

## 已知限制

- 部分旧组团仍有合在底图中的建筑和植被，需要单独测量落地面与遮挡裁片。路线格网的连通性检查只覆盖已标注为可通行的地面。
- 未删除旧主线素材。保留 Web、求是湖及其他场景仍可能使用它们，不能仅因新校园 manifest 不引用就移除。
