# 启真湖黑天鹅出场：独立 Godot 验证

状态：Draft。先验证 7.2 秒出场及交还操作；不替换正式主剧情。

## 运行与恢复

使用 Godot 4.6.3。仓库已有原资源同步流程时，可直接打开
`scenes/qizhen_swan_entrance_preview.tscn` 并按 F6。
可恢复的独立工程生成方法（须先同步原有湖地图、船、字体、声音资源）：

```sh
python3 godot_native/tools/package_swan_entrance.py /tmp/7-55_Qizhen_Swan_Entrance
# 用 Godot 打开输出目录的 project.godot，导入后 F5
```

独立工程无主游戏 autoload，不读写正式存档。默认入口就是此验证场景。
打包文件只含所需源文件和原资源，不需要整仓库或视频即可恢复运行。

## 本轮可检查内容

- 0–1.4 秒：原围栏位置的水纹、门叶松开、天鹅显现
- 1.4–3 秒：从西侧围栏开口游出，镜头跟随
- 3–4.75 秒：抬头、朝船转向、短暂停顿与蓄势
- 4.75–5.85 秒：完整身体姿态切换，展翅拍水
- 5.85–7.2 秒：扑近、镜头拉回，同一艘船恢复操作
- 后续：短范围划桨验证。出围栏南口后停留在同一画面；不跳转手机页，不写章节完成

船、纸条、天鹅、水花、尾波、门叶各自绘制。地图保持原图坐标。
交还操作及跳过后均有 3.5 秒追逐接触保护，避免停在天鹅嘴边立即失败。
局部追逐模型提供有限转向、锁向冲刺预兆及障碍阻挡；不是完整寻路系统。

操作：A/D 或左右键划桨；S/下键配合划桨反划；鼠标点击或触屏上/下划左右桨按钮。
空格/Enter 跳过；R 重播；P/Esc 暂停。窗口失焦会暂停。

## 已完成的验证

```sh
godot --headless --path <独立工程> --editor --import --quit
godot --headless --path <独立工程> --script res://tests/test_qizhen_swan_entrance.gd
godot --headless --path <独立工程> --script res://tests/test_qizhen_swan_motion.gd
```

- 入口导入和脚本解析无错误
- 出场/交还/跳过/暂停/重试及输入模型：1440 项断言通过
- 天鹅转向/锁向/碰撞/保护：1615 项断言通过
- 云端原生窗口真实键盘操作验证：R 重播、Space 跳过、A/D 划桨、P 暂停。截图确认重播回到封闭门初态，跳过后原船可操作，暂停停留在同场景
- 触屏通过 Input.parse_input_event 输入分发，验证一次反划及一次暂停；模拟鼠标被过滤，独立工程也关闭触摸转鼠标，避免重复输入；尚未在实体手机验收
- 390×844 原生 SubViewport 渲染：17 项按钮边界和船可见性检查通过，出场/交还/暂停截图已验视
- 修复原南岸数据的西南黑区缺口；南口下段按原图保守限制到 x292..425，并验证旋转船体完整包围盒；到达优先于同帧抓捕
- 18 次测试划桨意图驶出校准后的南口，每帧完整船体通过碰撞校验；仅证明这条短路线，不代表整湖导航已验收

## 视频的准确含义

提供的视频由 Godot 4.6.3 Movie Maker 原生渲染，1280×720，固定 30 fps，360 帧，共 12 秒。
前 7.2 秒是出场，后段是测试脚本发出 18 次划桨意图，真实船模型驶出南口。
没有逐帧改写船位；但这是确定性脚本输入演示，不是人工操作通关。

云端 llvmpipe 录制日志：12 秒画面用时 11 秒；CPU render 平均 1.05 ms/frame；GPU render 4.46 ms/frame；编码 13.75 ms/frame。
这些是离线固定帧率录制指标，不能据此宣称实体手机或用户电脑达到某帧率。
