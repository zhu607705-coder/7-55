# Native dorm object slice

Scope: source dorm desk/card, optional cabinet/lights, and the existing exit. The original 941×1672 dorm plate, furniture footprints, player art and source coordinates are unchanged. This is a bounded native slice, not complete dorm object decomposition or a full campaign acceptance claim.

## Objects and authority

- `DormOriginalObjects` owns independent Godot card/cabinet/lamp/door nodes. The card repeats the original `DormHubScene.createCampusCardPickup` 40×26 geometry and palette. It is an added real object; the plate's yellow note remains untouched.
- `c2_recover_card` retains its original predicates and immediate item, phase and inventory commits. The shell opens the real restored world bag. A 460 ms non-interactive copy slides away from the source desk, then settles toward the existing inventory slot. It stays aligned when the bag changes viewport dimensions.
- Cabinet panels use regions of the original plate, opening/closing around the outer edges in 260 ms. Desk lamps toggle independently in 220 ms. Their three stable optional booleans live in validated `native.dorm_props`. They never grant an item or affect any story gate.
- `c2_dorm_exit` keeps its original `movement_ready`, `canLeaveDorm`, and `manualControlTested` checks. Rejection gives the existing message plus 180 ms of handle/leaf resistance. Success commits the original campus scene/checkpoint immediately, then draws a 380 ms read-only old-door leaf reveal clipped to the intersection of the former world content area and the current arrival HUD boundary. New input can dismiss it.
- Always-near character inspection is a keyboard fallback. Nearby authored furniture and the exit can receive Space; picking and inventory-drop geometry retain their existing owners.
- Naming, valid exercise, gamepad purchase/use, real first movement and the existing library reservation remain controller-owned. No animation writes or synthesizes those facts.

## Lifecycle and accessibility

Copies never own input, collisions, the camera, sound or progression. Phone/modal changes, state replacement, incompatible scene changes, resize during exit, and destruction clear transient copies. Reload restores accepted facts and stable furniture positions, without replay or duplicate rewards. Reduced motion removes card translation/rotation and door deformation while retaining state distinction and the same original controller timing.

No new sound is emitted. Existing accepted-action audio remains single-owned.

## Verification

`tests/test_dorm_native_objects.gd` covers 88 checks at 1180×812 and 390×844, including:

- Original pickup proximity before movement capability; immediate actual bag opening
- Repeated pickup, unchanged item facts, 460 ms tail lifetime, phone and scene cancellation
- Cabinet reversal, independent lamps, optional-state save validation and ordinary reload
- Naming/exercise prerequisites; real keyboard displacement and shared touch movement path
- First movement does not bypass original reservation; locked/earned exits and immediate campus transition
- Keyboard priority for cabinet/exit; exit input interruption and ordinary campus reload
- Reduced motion and root-level overlay cleanup

`tests/capture_dorm_manual.gd` is an explicit source-checkpoint QA harness. F6: pickup, F7: earned exit, F8: cabinet, F9: locked door, F10: 1180×812 / 390×844. It records actual keyboard/pointer actions and framebuffer screenshots. Test positioning is declared and does not claim earned full-campaign navigation. A 390×844 desktop window is mobile-layout evidence, not a physical Android/iPhone test.

Run with isolated XDG directories:

`godot --headless --path godot_native --script res://tests/test_dorm_native_objects.gd`
