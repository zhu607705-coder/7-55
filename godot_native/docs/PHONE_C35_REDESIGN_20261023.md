# 第 3.5 章手机交互与纸墨像素界面

2026-10-23。用户认可章节入口概念图，并要求保留纸墨细像素感觉，参考 Telegram 和苹果官方设计文档，让每页围绕实际操作组织。本轮实现范围是第 3.5 章全部手机证据页、共用手机状态栏和旧通用标题栏中的无功能省略号；其他章节应用的完整重设计不在本轮验收中。

## 官方参考与具体取舍

- [Apple HIG · Status bars](https://developer.apple.com/design/human-interface-guidelines/status-bars)：状态信息保持可读，避免让位于状态栏下的内容看起来可操作。这里采用无边框时钟、网络和电池图形；游戏任务在第 3.5 章放在应用导航区，物品栏保留左侧吸附和折叠，章节封面只突出开始操作。
- [Apple HIG · Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：标题说明当前所在页面，返回沿内容层级退回，少量主要操作与内容分开。这里的导航栏固定，长内容拥有一个滚动区域，提交/保存留在底部操作区；没有可执行命令的旧省略号已移除。
- [Apple HIG · Collections](https://developer.apple.com/design/human-interface-guidelines/collections)：照片按视觉内容浏览；查看原图、选择帧、提交顺序分成三个不同操作。
- [Apple HIG · Playing audio](https://developer.apple.com/design/human-interface-guidelines/playing-audio)：播放/暂停保持原本含义，并与实际播放器一致。复用原音频会话、真实波形与播放位置；未充分试听的文件不能保留为候选，返回/失焦仍取消会话。
- [Telegram 官方截图](https://telegram.org/tour/screenshots)、[官方界面更新说明](https://telegram.org/blog/crafting-android-design-and-more)：借鉴清楚的导航标题、消息流和内容/操作层级，保留水墨插画与晨札像素字体；应用界面遵循用户后续指定的微信白色、浅灰与绿色。未复刻品牌、商标或引入 Telegram 服务。

这些是 Godot 内部模拟手机的交互依据，并不表示调用了 iOS 的系统状态栏、系统相册或系统媒体服务。

## 微信与侧边物品栏

微信使用用户提供的桌面截图作为结构参考，适配为手机里的「会话列表 → 单个会话 → 返回列表」。列表搜索能实际筛选会话并显示空结果；原朋友、室友、导师头像中的剧情交互保留。朋友对话的原有玩家回复位于右侧绿色气泡，玩家头像随同回复显隐。第 3.5 章归档群聊使用方形头像、昵称与左侧浅色气泡；底部操作属于选取消息并保存截图，不提供虚构的自由发送。

物品栏仍是可折叠抽屉，吸附在左侧并可沿侧边上下拖动。展开/收起、拖动物品、组合与查看继续使用同一套控制器和手势。桌面有空间时，收起把手贴在手机外侧；紧凑屏幕的把手叠在侧边，展开抽屉以浮层呈现，不占用永久内容列。拖动不会把物品栏移入导航栏，也不会误触折叠。

## 统一配色修正

用户明确要求按微信原来的白色呈现。`phone_palette.gd` 统一正文浅灰 `#ededed`、状态栏/导航/底部操作区 `#f7f7f7`、白色卡片 `#ffffff`、主文字 `#202020`、次文字 `#6b6b6b`、分隔线 `#d9d9d9`、主要操作 `#16894b`。自己的消息保留微信绿色 `#95ec69`，选择与播放状态使用同系浅绿。章节封面使用白底，保留原插画与像素字体。头像和证据图片保留内容本身的颜色。

去掉卡片的黄纸装饰、红色播放描边和蓝色焦点；语音波形与选中状态使用相同绿色。无底色的状态/任务按钮也不再绘制整块灰色投影。

## 逐页的操作模型

| 页面 | 玩家在这里完成什么 | 呈现和操作边界 |
| --- | --- | --- |
| 章节封面 | 进入未同步记录 | 原生两行标题、一幅湖畔记忆插画、一句引子、一个开始按钮；开始只提交原有 `c35_begin`。没有缓存统计和多角色对白堆叠。 |
| 记录恢复 | 对照已有来源并判断时间与地点 | 仅显示已有证据恢复出的起止时间；起点未取得时保留原始划船帖入口。四个来源各有本地状态，排除理由先选择再确认；地点仍由原控制器验证。 |
| CC98 收尾 | 阅读原帖并发布一条收尾回复 | 保留作者、原文、照片、时间和两楼回复。选回复只形成草稿；固定发布按钮才请求收尾与保存时间。已发布后显示回执。 |
| 恢复照片 | 从七张候选里恢复连续三帧 | 图片点开可等比查看全图，编号按钮选入/移出顺序；顶部显示三张已选缩略图，确认是独立操作。大图返回相册，相册回到实际来源页。成功后不再提供重排或再次提交。 |
| 语音备忘录 | 试听、保留四段并排序 | 原会话控制播放/暂停和实际进度，试听不足时保留按钮不可用；筛选与排序有独立阶段，清空、重新筛选与上/下移继续走既有意图。成功后保留回听与归档结果。 |
| 楼宇通知 | 阅读并保存一份通知 | 文档型页面，标题、发布者、时间与原文分层；保存按钮固定在底部，保存后不可重复提交；群聊是另一个可返回的页面。 |
| 夜间自习群 | 从对话里选取两条入口信息 | 消息保留作者和原文；点整条消息切换选择，撤回记录呈现为系统消息。底部显示选择数量与独立保存操作，选满后其余候选不可选。 |
| 校园网络 | 筛选实际记录并保存候选 | 时间/会话/区域三个筛选器只影响结果列表，不能获取证据；每条记录保留接入点、身份和持续时间，明确保存后才提交原候选记录意图。不会自动选中正确答案。 |

`phone_app_frame.gd` 只管理手机内部导航、内容滚动和操作栏。帧为 424×814，仍位于唯一的 430×860 手机壳内，顶部 40 由共用状态栏占用。长页不再把导航栏和提交按钮卷进内容中。内容与操作栏左右均为 18 逻辑像素；取消原先额外预留的 36 像素，展开物品栏不会挤窄或移动内容。相册网格和大图分别保存滚动位置。

界面构建不写剧情；`scripts/chapters/c3_interlude.gd` 的证据、顺序、回放和地点验证保持原样，未改存档结构。插画只在章节封面绘制，不生成道具、路线、答案或碰撞。
