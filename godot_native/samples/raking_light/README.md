# 斜光找压痕 — 独立教室原型

Godot **4.7.1**, GL Compatibility。打开本目录的 `project.godot` 运行。

## 直接操作物件

- 一手拖纸面或铜色纸边，调整纸的两轴倾角；另一手拖灯罩，横向绕桌移动，向下拖以降低光源。
- 用掠射光寻找纸上浅压痕。停止调整约 1.4 秒，确认整条图形后，场内预览门打开。
- 上方小窗是旧照明的独立只读画面。可以挪开它；它不会移动当前的灯或纸。旧纸没有本次压痕，仅提示灯的位置和照射方向，不直接展示目标图形。
- 鼠标或单指可先调纸，再调灯。物件保持姿态，不要求一直双指按住。
- 右上角二级菜单/失焦/取消触点/出界/窗口改尺寸会松开所有owner；必须点“继续”后重新观察。重新摆放只重置此样段。

## 真实几何，不是文字谜题

纸张由160×120网格构成。压痕通过顶点凹陷和其表面法线生成。StandardMaterial3D接受实际SpotLight3D照明，没有墨线贴图、按进度显示图案或屏幕空间解谜覆盖层。成功依据来自同一灯/纸几何的入射角、光锥覆盖和凹槽两侧法线光照差，还需实际调整纸与灯并稳定观察。

相机保持既有样段的正交50°俯角/8°偏转。纸下缘随倾斜自动抬高，不穿入纸托。当前和旧照明有各自的World3D、网格、材质和灯。

纸上图案是明确的**原型路线符号**，不代表真实教学楼房间。预览门是局部完成反馈，未接入正式地图、剧情、inventory、存档或 `minute-card-paper` 证据。原 `paper_rewind` 样段没有修改或运行时依赖。

```sh
GODOT_BIN=/path/to/Godot_v4.7.1-stable_linux.x86_64 node tools/run.mjs
node tests/test_isolation.mjs
```

干净复制导入；模型/真实几何/触点owner/中断测试；普通启动；正式存档哨兵保持不变。录制脚本只发送普通输入，不写解谜状态。`.github/workflows/raking-light-demo.yml` 使用Xvfb/Mesa真正GL渲染，输出手机比例视频和PNG。Headless通过不表示视觉通过；托管触点也不表示物理手机验收。浏览器和物理移动设备性能尚未验收。
