# 3F pantry: steady tea delivery

Historical first-pass receipt. The current source adds empty glasses, slow water filling and coupled portion/balance constraints; see [the slow-water extension](PANTRY_WATER_20261030.md). The measurements below describe the earlier prefilled version only.

The existing third-floor charcoal communal table now opens a fifth playable room prototype. The player swaps actual cups, lifts a physical handle, observes the loaded tray, then carries a balanced tray to the sofa coffee table. No gameplay button strip or keyboard input is required. The room remains the existing pixel-art space; the closeup extends the fixed orthographic miniature system.

## Play

- Local export: `http://127.0.0.1:8139/pantry_20261030/?area=pantry` (requires the existing local server).
- Click the tray or charcoal table beside the character. Drag one cup onto another cup to exchange them.
- Pull the orange handle upward to test. A heavy side tilts downward, while the exposed tea surface remains horizontal.
- Once the tray is level, drag its handle toward the rear coffee table. A completed delivery moves the independent room prop from the communal table to the existing sofa coffee table.
- Pull the delivered tray back to try again. The newly available orange front tab shifts the support line for an optional harder variation.
- The loose notebook supplies three clues only when opened and paged by the player. Exit is ordinary navigation.

This remains an isolated sample with session-only results. The proposed seated-student payoff, production chapter integration and persistent saves are not implemented. Difficulty/time estimates remain author predictions, not novice playtest measurements.

## Authority and recovery

`pantry_tray_model.gd` owns the four cups, support, configuration revision, trial, lift and delivery phases. Loads are 1, 1, 2, 2 (equal glass mass plus visible tea); the four arms are −2, −1, +1, +2. The presentation reads this model and does not grant results. A lift alone is insufficient: completion requires the same configuration to remain stable through delivery. Several equivalent arrangements succeed.

Invalid drops animate back to the original cup position. Cancellation and focus loss end unfinished trials without losing cups or an already earned delivery. Another finger cannot commit an owned drag. Reduced motion removes decorative easing/ripples while preserving necessary state changes. No production autoload, inventory, quest or save is accessed.

All three floor manifests, existing furniture footprints, source imagery, doors, stairs and elevator links are retained. The new table interaction uses an existing legal approach point, cancels room movement while the closeup is active, and restores the same feet on exit. Four previous puzzle entries remain available.

## Reproduce

Set `GODOT_BIN` to the pinned executable, then run:

```sh
node godot_native/samples/future_learning_center/run.mjs --pantry-test --headless
FLC_CAPTURE_DIR=/absolute/path/desktop node godot_native/samples/future_learning_center/run.mjs --pantry-input-test --resolution 1280x720
FLC_TOUCH=1 FLC_CAPTURE_DIR=/absolute/path/mobile node godot_native/samples/future_learning_center/run.mjs --pantry-input-test --resolution 844x390
node godot_native/samples/future_learning_center/run.mjs --test --headless
```

Export with the matching `GODOT_WEB_TEMPLATE` using `build_web.mjs <output-directory>`, then enter `?area=pantry`. All runner profiles are isolated from the real player save. No new raster assets were created; the tray, liquid, handle and room closeup are native meshes using the incumbent camera/material system.
