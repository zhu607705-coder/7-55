# 同一物件的动作与操作台投影修正

本轮对应用户提出的两个问题：同一物件的变化过少，以及近景中所谓 45 度俯视实际混用了不同投影。继续遵守场景物件优先准则，范围为当前四种独立操作台试玩。

## 投影

`bench_projection.gd` 统一使用正交相机的 45° 俯角、零偏航：X 轴水平，地面深度乘 `sin(45°)`，高度乘 `cos(45°)` 向上投影。台面相对边保持平行；其材质取自已有空台面的无物件区域，不再把原图的梯形收窄和正面支架整张铺到近景中。

轨道使用同一投影下的方形模块，格距为 `114 × 114·sin(45°)`；模块转动时先连续旋转，合法松手后才提交四分之一转。模型仍是原来的五列三行拓扑，送达和空车返程要求不变。车辆四向可见尺寸与停止余量读取新贴图的实测帧，不借助缩小碰撞绕过障碍。

齿轮、环、零件、箱体和太阳能板使用同一地面/高度基向量；面板围绕真实铰链转动，同时改变深度与高度，不再用固定向右偏移的斜四边形代替。显示器的立面、支架和落在桌面的底座分别按对应平面绘制。接收屏移动时，插座和线缆端点保持附着。

45° 俯视会让 30° 与 60° 的面板具有相同轮廓，因此面板额外保留真实深度/高度推导的外露后支撑杆和安装脚，面板受光也随实际倾角、既有日照角及光强改变。两种稳定状态在正常和减少动效模式中均可通过机构与明暗辨识，临时角度文字不承担此职责。显示器支杆沿正高度方向连接屏体和底座，底座保持在零件盘之前可见的桌面区域。

新车辆及控件由内置 `image_gen` 基于原素材生成，保留蓝灰金属、奶油白、橡胶和黄铜及细像素方向。透明原始文件、完整提示、实测帧和 SHA-256 在 `assets/puzzles/oblique45_*` 及 `sources/` 中留存。运行 PNG 只增加文本来源元数据，原始像素保持不变。生成提示中的 45° 是美术约束，不代替对手绘栅格每个像素的几何验收。

楼层底图、房间相邻关系、墙体、门、电梯、楼梯、玩家脚框与房间镜头均未因此重新布局。

## 同一物件的状态变化

- **太阳能板与车辆**：铰链跟随拖动并落到目标角度；新面板装入后短暂落稳，轮转由真实行驶距离驱动。台灯移动时，灯具与待确认光照共同预览。
- **轨道与机器人**：抓取模块时显示离桌高度；模块连续转动，送货、卸货及空车返回继续使用真实轨迹；实际受阻后出现局部制动反馈。
- **齿轮与皮带**：抓取、装轴和落稳是分开的状态；齿轮齿面有投影厚度，皮带接缝跟随传动，松带会显示局部摆动，送料块保持真实位移。
- **插头、线缆与屏幕**：线缆弯曲连接实际插头，抓住输入端时同一根线随端点移动；信号包只在模型实际传输时沿线前进；屏幕接收后短暂扫过新图案，不代替第二次不同改稿。
- **共同反馈**：实体拉杆短暂落位，装配处使用有边界的接触弧。无效/取消的零件会退回托盘；回退中的物件按当前可见位置抓取。退出和失焦清除未完成的表现。

动效不会写入、开始或完成任何判题结果。浏览器读取系统减少动效偏好；原生验收支持 `FLC_REDUCED_MOTION=1`，接口 `set_reduced_motion()` 保留即时状态反馈而减少附加位移。原有正常实时 30 秒竞赛仍单独验收。

## 验证入口

```sh
GODOT_BIN=/path/to/Godot-4.7.1 node godot_native/samples/future_learning_center/run.mjs --presentation-test --resolution 1280x720
FLC_TOUCH=1 FLC_CAPTURE_DIR=/absolute/mobile GODOT_BIN=/path/to/Godot-4.7.1 node godot_native/samples/future_learning_center/run.mjs --object-input-test --resolution 844x390
```

`--presentation-test` 通过真实鼠标或触屏事件检查中间状态、渲染变化、取消回退、重新抓取、失焦和减少动效。可选 `--write-movie /absolute/frame.png --fixed-fps 30` 从真实原生渲染器记录固定步长演示；macOS 的独立测试配置以 960×540 记录，不修改正式项目配置，固定步长演示不替代正常实时输入验收。

精确结果、代码哈希、浏览器范围及独立审阅见 `PROJECTION_MOTION_VERIFICATION_20261030.json`。这是四种独立试玩的修订，不推定正式存档接入、完整 25 房间实现、实机或发布验收。
