# Authing 配置：需要账号持有人做的部分

平台代码已具备第三方登录发起、回调校验、账号关联和退出能力。2026-11-01 已连接真实 Authing 应用，本机 3001 可进入真实托管登录页；玩家注册、登录回调、验证、找回与退出尚需本人参与联调，见 [实际配置进展](authing-configuration-status.md)。下面保留新环境的配置步骤。首轮先用免费版，暂不购买付费套餐。

## 1. 注册并创建应用

打开 [Authing 官网](https://www.authing.cn/)，注册开发者账号，进入控制台。创建用于校园共创平台的用户池，在“应用 → 自建应用”里创建 **Web 应用**，名称可以填“浙大校园共创平台”。这是有后端保管密钥的应用，不要按纯前端应用把密钥放进浏览器。

应用后台具体菜单可能调整。按官方 [普通 Web 应用接入说明](https://docs.authing.cn/v2/en/guides/basics/platform-guide/integrate-with-regular-web-app.html) 找到应用信息、OIDC 协议、应用配置和登录控制。

OIDC（OpenID Connect，开放身份连接）是一套第三方告诉我们“这个用户是谁”的标准协议，平台用授权码模式：用户去 Authing 验证，服务器收到一次性授权码，再向 Authing核实身份。我们另加 PKCE（Proof Key for Code Exchange，授权码校验），将发起登录和换取身份绑定起来，防止截获的授权码被别处使用。

## 2. 配置协议和登录方式

| 后台项目 | 填写 / 选择 |
|---|---|
| 授权模式 | `authorization_code` |
| 返回类型 | `code` |
| ID Token 签名算法 | **`RS256`**，必须与当前代码一致 |
| 换取 Token 身份验证方式 | **`client_secret_post`**，服务器用应用密钥验证，不选 `none` |
| 返回模式（如后台有此项） | `query`，回调使用 GET |
| 登录与注册 | 启用用户名密码注册/登录，可选邮箱密码注册/登录，不要求手机号或学号 |
| 邮箱验证、忘记密码 | 在 Authing 的登录控制中配置并实际测试 |

平台只请求 `openid` 身份范围，不向自己的数据库复制邮箱、手机号、密码或第三方令牌。不要把要求学号或手机号的额外表单设成注册必填。

首轮默认密码登录，支持用户名与邮箱，避免每次登录都发验证码；没有邮箱的用户名账号仍需另行确认恢复方式，目前没有验收恢复码。邮箱验证和找回仍会发邮件。免费池目前每日 50 封邮件；2026-11-01 实际控制台提示还需完成实名认证/企业认证才能使用该额度（自 2025-10-12 起），以控制台实时权益为准；不要为测试默认购买专业版。[登录控制](https://docs.authing.cn/v2/guides/app-new/create-app/login-control.html) · [价格](https://www.authing.cn/pricing/)

## 3. 填写回调地址

回调就是 Authing 验证完后，将用户送回平台的地址。必须完整一致，不能混用 localhost、127.0.0.1 或端口。

| 使用方式 | 登录回调 URL | 登出回调 URL |
|---|---|---|
| 开发服务器（`npm run dev`） | `http://127.0.0.1:5174/api/v1/auth/callback` | `http://127.0.0.1:5174/` |
| 本机生产预览（3001） | `http://127.0.0.1:3001/api/v1/auth/callback` | `http://127.0.0.1:3001/` |
| 正式域名 | `https://你的平台域名/api/v1/auth/callback` | `https://你的平台域名/` |

先配置实际使用的一组，后台允许多条时可同时添加开发和正式地址。没有域名时先配置 5174 开发地址即可，不需要先付费买 Authing 的登录自定义域名。如果控制台要求配置应用网址或允许来源，填写对应的 `http://127.0.0.1:5174` 或实际 HTTPS 平台域名。

这是同源后端模式，浏览器不直接向 Authing 发跨域令牌请求。不要为方便而把允许回调或来源设置成任意 `*`。

## 4. 复制配置到本地 `.env`

应用详情里获取三项：Issuer URL（颁发身份的地址）、App ID / Client ID（应用编号）、App Secret / Client Secret（应用密钥）。Issuer 通常形如 `https://应用名.authing.cn/oidc`，**请复制端点信息里的实际 issuer，不要照抄示例或只填域名**。

写入 `platform/.env`：

```dotenv
PUBLIC_ORIGIN=http://127.0.0.1:5174
AUTHING_ISSUER=https://你的应用认证域名/oidc
AUTHING_CLIENT_ID=你的应用编号
AUTHING_CLIENT_SECRET=你的应用密钥
OPERATOR_SUBJECTS=
GAME_URL=
```

三项 Authing 配置必须一起填写；全空表示未配置，部分填写会拒绝启动。`.env` 已被 Git 忽略。密钥只放本地或服务器配置中，不发在聊天、文档截图或代码里，也不要加 `VITE_` 前缀。

重启：

```bash
npm run build
npm run db:migrate
npm run dev
```

访问 `/api/v1/auth/config` 的 `configured: true` 只表示配置已提供，不证明服务在线；点击“前往登录 / 注册”完成真实登录才算联调成功。配置错误、服务不可达或验证码收不到时，检查 Authing 应用设置与邮件额度；不要绕过验签或关闭校验。

## 5. 指定运营账号

让运营同学先通过 Authing 注册并登录一次。在 Authing 控制台“用户管理”里找到其**用户 ID**（标准身份 `subject`，即 `sub`），填入服务器的 `OPERATOR_SUBJECTS`，多个人用英文逗号分隔：

```dotenv
OPERATOR_SUBJECTS=运营同学的Authing用户ID,开发负责人的Authing用户ID
```

重启服务后，这些账号会出现“运营工作台”。普通用户不能注册成为运营；不使用昵称或邮箱来判断权限。要撤销权限，从此配置删掉 ID 并重启，已有平台会话也会按新列表判断。

可选 `GAME_URL` 填经团队确认的正式 HTTPS 试玩地址，配置后网站显示“试玩游戏”；没有地址时保持空，不展示假入口。单条投稿的具体试玩链接由运营处理时分别添加。

## 6. 真正对外前的联调

用两个真实测试账号检查：邮箱注册/验证、密码找回、登录返回、昵称修改、退出后另一账号登录、草稿回到投稿窗口。再检查匿名内容、阅读进度、点赞评分、运营推进与试玩链接。手机微信内浏览器也需实测。

目前平台会话最长 8 小时。退出会即时撤销当前平台会话，然后使用 Authing 官方文档的 `/login/profile/logout` 结束其浏览器登录。未实现 Authing 管理端封禁/改密后自动撤销全部平台会话的通知机制；在完成该机制之前，相关操作的影响不会被夸大成即时全端下线。

本地旧版账号不再接受密码登录；迁移 003 撤销其会话并删除旧密码摘要，内容保留。若已有真实用户贡献需要迁入 Authing，应核实归属后专项迁移，不能按相同昵称或邮箱自动认领。

微信/QQ 暂不作为首期必配项。微信网站扫码还需要自己的微信开放平台网站应用及相应资格，第三方认证服务不能替代申请。
