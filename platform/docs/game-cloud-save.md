# 《7:55》账号云存档

更新于 2026-11-03。已在主分支 `72fe2ed3dab84c99cedb2e427a4d639fca135472` 上整合账号云存档和共创入口，使用官方 Godot 4.7.1 完整导出。当前整合验证见 [20261103 记录](integration-20261103.md)。代码通过功能分支和合并请求交付；正式域名、服务器与实体手机跨设备验收仍待完成。

## 玩家规则

- 游客可直接试玩；旧版无账号本机档只归游客，不自动归给首位登录者。
- 登录复用共创平台同一个 Authing 玩家身份。每账号一条主进度、上一份有效备份、最近一次重新开始前备份。
- 游客带入、云端与本机冲突都明确选择；选择前不覆盖。章节、任务、保存时间和同步状态显示在入口与存档管理中。
- 重新开始需要确认，服务器先完成备份和新进度写入再进入开场；保留个人编辑内容。恢复备份前也确认，恢复前主进度转为上一份备份。
- 账号游玩要求联网。检测到离线、请求超时、会话失效或账号变化后暂停；只在重新核实身份、版本并完成选择后恢复。主动断网会立即触发，服务不可达由请求超时与 15 秒身份心跳检出，并非承诺零延迟发现。
- 主线恢复仍遵循原生安全检查点，追逐或动画不逐帧恢复。云存档不作为兑奖、排行榜或可信通关证明，不修改共创的防剧透偏好。

游戏不导入平台运行代码；平台不导入游戏运行代码或剧情源码。平台只做存储格式、附件及摘要一致性检查，游戏校验全部剧情状态。运营没有读取其他玩家存档的默认入口。

本机路径为 `user://profiles/guest/` 或 `user://profiles/<member UUID>/`，包含主档、上一份本机备份、照片、个人编辑文档与同步记录。原生桌面版沿用原 `user://` 行为。网页先暂停并确定归属，再开放游玩；未来版本本机档会阻止初始化，保留原字节。

完整包由原生状态封装、两个个人编辑文档、照片指纹清单及展示摘要组成。照片使用内容 SHA-256（检查文件内容的指纹），先以 HEAD 检查本人附件是否已有，再只上传缺少的内容；所有照片齐全才能提交快照。下载先校验完整状态、文档和图片，安装失败恢复原文件与内存状态。

自动保存停止变化约 2 秒后上传，连续变化最长约 10 秒；手动保存立即发起。个人编辑文件变化另行检测。只有服务器确认的那份冻结内容能获得“云端已保存”；并发生成的新进度仍显示待同步。本机持久化不是只确认内存文件存在，还要等 IndexedDB 中的文件摘要逐项匹配。

## 接口

均在 `/api/v1/me/game-save`，本人归属来自服务端会话，不接受用别人的账号编号查档。读请求可附 `X-755-Member`；写请求另需精确 Origin 与 `X-Requested-With: 755-platform`。

| 方法与后缀 | 用途 |
|---|---|
| `GET` 空后缀 | 本人主档、两类备份摘要和版本 |
| `GET /snapshots/:id` | 读取本人当前仍保留的完整快照 |
| `PUT` 空后缀 | 自动或手动保存 |
| `POST /restart` | 备份后建立新主线 |
| `POST /restore` | 恢复保留的备份 |
| `HEAD /assets/:sha` | 本人照片是否已存在，无图片传输 |
| `PUT /assets/:sha`、`GET /assets/:sha` | 上传、下载本人 PNG |

写入包括 `expectedMemberId`、`expectedRevision`、`operationId`。账号不符或版本落后返回 409；同操作同内容重试不重复轮换备份；旧操作成功后云端又有新版本时也返回 409，不能把旧回执误报为当前档。操作回执保留至少 24 小时，过期后旧版本仍会被版本检查拒绝。跨标签页消息只有“变化”提示，收到后重新向服务器查身份与版本。

核心状态 8 MiB、每份编辑文档 8 MiB、单张照片 12 MiB、最多 4 个不同照片指纹、照片合计 32 MiB；每账号逻辑容量 256 MiB。普通共创请求仍为 64 KiB，只有存档提交和图片路由拥有专门上限。只保留三类指针引用的快照；未被引用的照片超过 24 小时后，在该账号后续上传/写入时清理，不是定时立即删除。

## 本机运行与上线顺序

本机 `.env`（不入 Git）已设置 `PUBLIC_ORIGIN=http://127.0.0.1:3001`、`SERVE_WEB=true` 和 `LOCAL_GAME_EXPORT_DIR`，沿用现有 Authing 配置。该路径指向完整导出 `godot_native/exports/web-release`。以后重新启动可在平台目录执行 `npm start`；数据库也必须运行。`LOCAL_GAME_EXPORT_DIR` 仅用于开发，生产配置会拒绝它。

- 共创：`http://127.0.0.1:3001/`
- 游戏：`http://127.0.0.1:3001/game/`
- 迁移就绪：`http://127.0.0.1:3001/api/ready`

迁移不会在 API 启动时自动执行。本轮已先用 pg_dump 备份公共 schema，在临时数据库恢复并比较全部 13 张原有表的内容摘要一致，之后显式执行 004。本机备份在任务输出的私有目录，不在仓库。正式服务器仍须另外备份和演练。

正式上线继续用 `deploy/compose.game.yml` 和 `deploy/Caddyfile.with-game`，游戏独立导出、只读挂载。先备份数据库并执行兼容的新迁移、启动新版 API，再部署对应游戏包；修改正式域名与 Authing 回调。具体操作见 [域名与部署](domain-deployment.md)。GitHub 上传代码不会启动数据库或云存档 API。
