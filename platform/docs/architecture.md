# 共创平台实现边界

2026-10-24：认证交给 Authing，平台负责用户贡献、意见与团队处理记录。React 负责交互；Fastify 负责 HTTP；Zod 负责运行时字段校验；PostgreSQL 负责共享持久化。应用说明见 README，具体 Authing 操作见 authing-setup.md。

## 代码与数据所有权

`apps/web → packages/contracts`；`apps/api → packages/contracts/packages/database`；`packages/database → packages/contracts`。游戏存档、控制器和剧情不进入平台。公开展示素材独立复制并保留来源。

001 是公开章节范围；002 是原社区表；追加 003 迁移引入第三方身份、一次性登录事务、投稿渠道/权限/处理状态、进度时间线、运营审计和作者授权记录。历史 SQL 不改，主进程不自动迁移。

## 身份

2026-11-02 用户明确要求游戏与共创平台共用一个玩家账号。首期目标为同一 Authing 应用与同站点会话，游戏仍独立构建，剧情内的角色登录谜题保持独立。实际游戏接入尚未实现；设计与验收顺序见 [共用玩家账号](shared-player-account.md)。

Authing 配置通过服务器环境变量提供。openid-client 执行标准 OIDC 授权码交换，PKCE、state、nonce、RS256 签名、issuer、audience 和过期时间均校验。发现配置在实际登录时加载，有超时与失败后重试，未配置时保留公开浏览。回调请求日志移除查询参数，错误不回传提供商原始内容。

一次性登录事务 10 分钟失效，绑定独立 HttpOnly Cookie；在数据库中原子消费，防重放、跨浏览器和多实例竞态。业务身份按 issuer+subject 唯一，事务锁串行化首次登录。平台不获取 email/phone 资料，不存第三方令牌与密码，也不按邮箱自动合并旧账号。

平台会话最多 8 小时；Cookie 为 HttpOnly、SameSite=Lax，HTTPS 下 Secure 与 __Host- 前缀；数据库仅存随机令牌 SHA-256 摘要。退出撤销当前会话并使用 Authing 的浏览器登出地址。管理端封禁、改密后的全平台即时撤销尚未接通，不能夸大远端撤销能力。

## 内容访问与权限

游客只能浏览/写本地草稿。所有业务写入检查 Origin、自定义请求头和数据库持久化限流。运营身份来自当前 issuer 的服务器 subject 列表，每次请求重新判断；用户输入和昵称不参与提权。

公开查询在数据库层排除私密章节、撤回和被隐藏的投稿；本章说只查询玩家自设阅读范围内内容。列表、搜索、详情、记录和互动共用这一边界。自设阅读进度是防剧透偏好，不是游戏通关权限。

剧透标题/正文/进展默认不下发；明确 reveal 请求才加载，且不能绕过章节可见范围。匿名作者在响应构造时去除真实 ID/昵称，author 权限由 isOwner 明确表示；私下作者关联仍保存在服务器。

点赞和评分有唯一键，事务行锁与删除/隐藏串行，防止并发累计或在隐藏后继续互动。用户账号意见不等于自然人实名票。

## 运营与授权

运营进展使用预期 revision 防覆盖，状态路径显式校验，必须有回复；试玩/发布必须有 HTTPS URL 和版本。故事未授权不能推进制作。生产里程碑只前进不回退，状态退回不恢复自行撤稿或撤销授权资格。

授权与署名变更、投稿进度和隐藏原因分别记录；隐藏原因只在内部审计表，不出现在公开回复中。作者改成匿名署名会同步清除平台历史进展中的署名；已发布游戏文件仍需团队人工更新。运营提供链接不替代内容授权或游戏发布验收。

## 部署与交接

网页与接口同源，分享地址使用当前实际域名；不配置任意跨域。数据库和应用端口不公网映射。Docker/Caddy 配置已准备，本机未启动容器；域名部署仍需实际环境验收。备份包括用户内容、身份关联和授权记录，应单独保存并演练恢复。

北化复用代码采用独立数据库、身份应用、域名和运营配置。当前没有跨学校共用数据库或“租户”隔离实现，不得仅改校园标题就把两个学校的数据混用。
