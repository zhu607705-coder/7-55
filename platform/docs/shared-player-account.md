# 游戏与共创平台共用玩家账号

更新于 2026-11-03。游戏 `/game/` 与共创 `/` 使用同站点、同一 Authing 应用、同一个平台会话。玩家只注册一次，公开昵称与登录用户名分开；普通玩家不因登录获得运营权限。Authing 密钥与令牌交换留在服务器，不通过 URL 或游戏脚本传递密码与令牌。

游戏启动页、手机控制中心和 F10 设置页提供共创与玩家账号入口。共创在新标签页打开，保留游戏；登录/退出后原游戏重新向服务器确认身份。游戏里“统一认证登录”仍是剧情谜题，与真实玩家认证分开。

账号云存档已经接入，并非只加了跳转。具体规则、代码边界、接口和验收见 [账号云存档](game-cloud-save.md)。账号切换、退出或断线会暂停账号游玩，不会把 A 的进度变成 B 的进度；游客进度只有明确选择后带入。

本机已挂载真实独立 Godot 导出：共创 `http://127.0.0.1:3001/`，游戏 `http://127.0.0.1:3001/game/`。登录返回允许精确 `/game/` 及查询/片段，仍拒绝外域、API、相似前缀和任意游戏子路径。完整游戏在隔离数据库、模拟签名身份服务下完成共享身份、重开/恢复与独立缓存恢复；不能用它替代正式域名和真实 Authing 云存档验收。

正式部署使用 `deploy/compose.game.yml` 与 `deploy/Caddyfile.with-game`，把独立构建的游戏只读挂到 `/game/`。保持原 GitHub Pages 域名的游戏，仅加普通链接不能共享本站 Cookie。现有身份映射使用 issuer + subject，后续更换应用须先验证身份语义并迁移，不能按邮箱自动合并。

## Authing 配置与尚待核实的边界

此前已经核实真实 Authing 登录回调、刷新保持会话、普通玩家访问运营接口被拒绝、退出撤销当前平台会话。本轮沿用既有配置，没有新建第二套账号、购买套餐或授权运营身份。

持有人已报告完成邮箱+密码注册及用户名必填补全。真实控制台最后一次独立读取确认了邮箱密码注册、用户名/邮箱密码登录和关闭用户名单独注册入口；“用户名、邮箱、密码必须齐全、旧账号不能跳过补全”仍需真实注册/旧账号验证，不能只凭报告当成验收。邮箱验证尚未开启，邮件能力仍需持有人处理。

当前发起认证使用 prompt=login，防止共用浏览器静默选择前一玩家。登录和退出本机回调仍为 3001，正式域名变化时须同步改 Authing、PUBLIC_ORIGIN 和 GAME_URL。
