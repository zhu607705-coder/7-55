# 2026-11-05 共创平台检查与优化

本文记录 2026-11-05 的本机验收。平台与游戏入口分别为 `http://127.0.0.1:3001/`、`/game/`。

## 已改动

- 同一个 HTTP 请求复用一次玩家身份查询；缓存不跨请求，退出与权限变更仍在下一请求重新核实。
- 同账号并发登录通过 PostgreSQL 事务和账号锁串行处理，最多保留 10 个会话。身份不匹配、插入失败会回滚，保留原会话。
- 限流记录不再每次写入都全表清理；每分钟最多清理 1,000 条过期窗口，实际计数仍由数据库原子更新。
- 首页和表单删去重复宣传文案，保留投稿、筛选、评分、进度与授权信息。修复桌面入口裁切，手机增加直接试玩入口，精简参与方式区域，调深次要文字、加大页脚说明。
- 便携导出复用主分支已有的打包修复，并额外禁止导出覆盖主档或上一份备份。开发预览仍不能自动保存或上传。
- 修复无进度变化时手动保存一直显示“同步中”；先确认本机持久化，再显示对应的云端保存时间。手动保存会等待已有自动上传结束，控制中心保存按钮显示真实结果；账号模式不再提示“仅当前浏览器保存”。
- 原有只读网页诊断也采集云存档弹窗的可见控件，便于普通点击验收，不新增进度写入能力。
- `@fastify/static` 从 10.1.7 升至 10.1.10，更新依赖锁文件，消除 glob/minimatch 依赖链的已知告警。没有更换认证协议或数据库结构。

## 正式 Authing 登录

本轮实际登录最初失败，浏览器报连接关闭；相同 Authing 域名直连正常，经本机代理失败。已保留原代理例外，添加 `authing.cn` 与 `*.authing.cn`，并同步代理软件配置文件。备份只在仓库外私有目录。曾观察到代理软件把系统例外覆盖回旧列表；之后再次核对持久配置文件与系统列表均已包含 Authing。未重启代理软件做持久性验收。

持有人随后亲自完成登录。后台核对 Authing 回调返回 302，建立 1 个有效玩家会话。本轮正式登录已通过；新账号完整注册、邮箱验证与找回没有重新验收，不能据此承诺全部认证分支无误。

平台自己的账号弹窗已采用像素样式。Authing 托管页样式在 `branding/authing-pixel.css`，已在真实表单预览电脑与 390px 手机尺寸。字体为现有 OFL 字体的改名子集，内嵌于 CSS，无第三方字体请求。**托管样式尚未保存至 Authing**：持有人已登录管理后台，但浏览器 DOM 控制持续超时，原生截图/点击也不能可靠操作页面。不能将本地预览说成后台已发布。

## 100 人并发

使用实际 loopback HTTP 与独立 PostgreSQL schema；身份提供方为签名测试服务。100 个不同玩家，10 波、每波 100 个同时发出的请求；数据库连接池保持 5 条连接。没有使用真实玩家存档或正式 Authing 压测。

| 场景 | 95% 请求耗时不超过 | 结果 |
| --- | ---: | --- |
| 浏览/会话，5 波 | 26 ms | 500 次成功 |
| 同一投稿点赞 | 52 ms | 100 次成功，落库 100 个赞 |
| 同一投稿评分 | 43 ms | 100 次成功，落库 100 条评分 |
| 不同账号保存 | 59 ms | 100 次成功，100 份独立主档 |
| 读取本人存档 | 16 ms | 100 次成功 |
| 同账号同版本竞争 | 36 ms | 1 成功、55 版本冲突、44 被限流；没有覆盖已提交的新版本 |

没有 5xx。前一轮同类测试的账号保存 p95 为 305 ms；最终运行本机其他负载较低，不能把差异归因于依赖升级。此结果对应本机、单热门投稿、小型状态包；未验证公网延迟、100 人同时上传大照片、长期持续压力或生产服务器容量。

## 本机验证记录

- 平台边界、类型、构建与行为测试：20 项通过。
- 静态文件依赖升级后，官方 npm 生产依赖审计为 0 条已知告警；这不等于没有未知漏洞。
- 真实 PostgreSQL 隔离测试：18 项通过，包含新增的 25 次并发登录、会话上限与失败回滚。
- 原生存档相关回归：6 项通过，覆盖账号/照片/编辑内容、持久化、便携导入、移动探索和之前失败的场景。
- 官方 Godot 4.7.1 使用现有完整资源导出，构建与内容摘要校验通过；产物如实标记未提交源码。
- 真实浏览器平台流程：签名测试账号登录、回调、投稿、点赞、评分、刷新保留、退出、换号隔离、390px 无横向溢出、手机游戏入口通过。两账号验证了投稿、支持与评分、刷新后保留、改分后人数不变、两种榜单排序，以及撤回后计数归零。
- 完整游戏：普通点击玩到手机主页，服务器确认任务“查看朋友的新消息”；独立缓存、390px 浏览器登录同一测试账号，点击继续恢复到手机主页。重新开始回到闹钟，并在服务器保留重开前备份。
- 最新完整网页包末轮验收通过：普通游玩到检查点、按钮确认保存、重复保存结束同步、重新开始保留备份、恢复回手机主页、断网暂停、重连核实后继续；7 项通过，页面错误为 0。此流程使用隔离测试身份与真实数据库。

安全回归覆盖了写入来源校验、账号/运营存档隔离、签名与登录重放、过期会话、并发版本冲突、操作重试、附件指纹、容量和事务回滚。本轮没有进行正式渗透测试或宣称不存在任何漏洞。
