# 启真湖可玩追逐验收记录

本次交付为独立 Godot 4.6.3 样例。默认入口是 `scenes/qizhen_playable_chase.tscn`。它不是正式剧情接入，也不写入正式存档。

## 旧版为何几秒结束

- 旧入口预览的划桨录制脚本在约3.24秒内注入18次输入，起点距原目标仅约500 px；开场保护3.5秒几乎覆盖整段
- 正式 CHANNEL 的横向路程约1090 px，原最大速度340 px/s，理想直线约3.2秒
- 原划桨观察场景只用于动作研究，没有完整追逐判胜闭环

因此本样例同时增加实体路线、锁向攻击、过口和低速停泊约束，并使用独立局部参数。它没有通过延长动画、计时自动成功或传送拉长流程。

## 局部数值与边界

| 项目 | 本样例 | 范围 |
| --- | --- | --- |

| 默认按住划桨节奏 | 0.46 s | 单指中央按钮和空格一致 |

| 冲刺 / 恢复 | 285 px/s，最长1.35 s / 3.4 s | 实体移动，碰撞与边界生效 |
| 船体碰撞 | 有向矩形38×22半尺寸 | 保留原地图28矩形，旋转和平移扫掠 |

## 视频与画面

交付视频“7-55-启真湖追逐-键盘实玩-暂停已剪短.mp4”48.066667秒，1180×812，约30fps实时X11采集。原始录屏没有使用Godot Movie Writer或固定帧率模拟。剪辑只去除较长的暂停观察区间，保留正常实时速度，没有插帧或人为重复帧凑60fps。

视频开头展示出场与闲置失败，后续展示成功的上路实玩。视频与源包的已知差异包括录制后将黄色实心闸条细化为双绳木桩，缩短窄屏按钮文案，并修正窄屏路线标签和结束面板布局；碰撞、路线和成功记录参数未变。另修复了“暂停出场时空格启动”的输入门控，新输入回归已覆盖。

## 本场景真实帧时

原生渲染窗口，1180×812，GL Compatibility，Mesa llvmpipe软件渲染器。无录屏、无Movie Writer、无fixed-fps、无FPS上限，V-Sync不受驱动支持而关闭。3秒暖机后采样22秒，共2761个实际渲染循环间隔。输入由脚本注入以形成追逐工作负载，包含tracking / charge_warning / charge / recovery四阶段，不作为人工实玩证据。

- 帧间隔 p50：7.729 ms
- 帧间隔 p95：10.078 ms
- p99：13.131 ms；最大45.505 ms
- 8帧超过16.667 ms
- Draw calls p50：92，p95：95

测量用单调时钟 `Time.get_ticks_usec()`。`Performance.TIME_PROCESS`是另一个引擎采样指标，不作为帧时/FPS。详见 `PLAYABLE_CHASE_PERFORMANCE.json`。这只说明这台云端机器的本次运行，不保证用户设备60fps；没有依据旧30fps视频做“性能修复”结论。
