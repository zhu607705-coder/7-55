# 7:55 · 启真湖大地图功能原型

这是可以打开、操控的独立 Godot 4.6 项目。它验证实际扩大的湖区、跟随镜头和更完整的湖上过程。

**这不是最终美术重建，也不是实地通航地图。** 目前的建筑、树木和岸线材质仍属于功能原型。原有游戏项目、剧情触发器与存档没有接入本项目。

## 2026-10-18 输入与镜头更新

本版修复连续划桨/暂停，增加左拖方向、右按划桨与目标直接点按；保持原图、美术、物理和路线。HUD 按真实画幅适配，地图 0.24 秒返回，字幕不随世界缩放。详见 `docs/INPUT_CAMERA_VERIFICATION_20261018.md`，本轮 70 项输入/镜头检查及原有 41 项审计通过。38 秒录像为原生自动输入回放，不是真机或人工游玩。

下方较早的全路线与性能数据保留为历史基线；本轮更新的证据以新报告为准。

## 打开与操作

1. 用 Godot 4.6.x 导入本目录的 `project.godot`
2. 等待首次资源导入后，按 F6/F5 或运行主场景 `scenes/qizhen_large_world.tscn`
3. Enter / 空格开始

| 操作 | 按键 |
|---|---|
| 连续交替划桨 | W / 空格 / 上箭头 |
| 左右转向 | A / D / 左右箭头 |
| 刹停、收桨 | S / 下箭头 |
| 检查信号、捞取物品、系泊 | 在目标附近低速按住 E |
| 查看整张湖区 | M；地图打开时不计游戏时间 |
| 暂停、继续 | P / Esc |
| 重新开始 | R |
| 触屏方向 | 左侧拖动方向 |
| 触屏划桨 | 右侧按住，松开收桨 |
| 触屏目标 | 靠近当前目标后直接点按，自动减速操作 |
| 触屏地图 / 暂停 | 右上角 图 / Ⅱ |

触控标记仅在触碰时显示；点按目标的优先级高于方向/划桨区域。焦点丢失、暂停、地图切换和画幅旋转会清除旧的按住状态。

## 一次完整的过程

五个可读阶段，由九个导航检查点串联：

1. 从北侧蓝色教学浮码头离岸
2. 在中央湖面停船，检查漂浮信号
3. 沿长岛西侧南下，绕到岛南取回防水袋
4. 沿东侧水道返航；经过有预警的黑天鹅冲刺区域
5. 回到浮码头，减速、船头朝北并系泊

信号与防水袋任务属于本原型的临时玩法验证，不代表已修改主线剧情。导航点是空间路标，不是新增九段剧情。

## 地形依据与游戏改编

- 2018 浙大官方航拍：保留湖、南部岛、北侧月牙形活动中心、东岸图书馆、两侧教学区的关系
- 2024 浙大官方校园图附件：提取不对称水面及长岛轮廓，作为北向上的地理骨架
- 2023 浙大皮划艇教学报道：支持图书馆/阳明桥附近蓝色模块式教学浮码头的存在
- 建筑细节、码头具体连接点、路线、目标、镜头与物件均为游戏适配
- 岛东支水道在原图轮廓基础上向东扩约 4 个源图像素。此修改用于控制空间，不意味着真实水道宽度
- 北桥与南部出口止于原型边界；不声明桥下净空、岛上连接桥净空、公众下水权限或连续可通航性
- 世界单位是游戏像素，**不是米**

参考链接和完整轮廓见 `docs/REFERENCE_GEOMETRY.json`。

## 已验证结果

在确定性输入控制器只发送正常的划桨、转向、刹停和交互输入时：

- 完成路线：110.692 秒
- 其中实际运动速度高于 30 像素/秒：106.183 秒
- 实际航行：25,559.99 世界像素
- 交替划桨：225 次
- 岸边接触：2 次；黑天鹅预警/冲刺：2 / 2；命中：0
- 41 项独立自动化检查通过，覆盖路线、碰撞、操作条件、暂停、地图、重开、焦点丢失等

成功路线没有位置瞬移，也没有人为设置“等够 90 秒才能通关”。这些数据是这一条成功验收路线的实测值，不是所有玩家最快路线的数学下界。

此前的完整路线 30 FPS 原生画面回放完成于 **108.642 秒**：25,553.66 像素、220 次划桨、0 次擦岸、0 次天鹅命中、2 次预警冲刺。它与上面的 60 Hz 审计是分别采样的两次运行，指标不能混为一条记录。

`tests/capture_full_route.gd` 用相同普通输入驱动真实 Godot 场景；画面带“自动输入回放”标记。它不是人工游玩录像。`tests/capture_stills.gd` 的定点画面用于地形检查，不是连续通关证据。

## 渲染与性能

- 静态地形只渲染一次，缓存为 2250 × 4000 纹理，以 4 倍最近邻缩放呈现
- 小艇、分层身体、船桨入水、水花、天鹅、提示与水面运动仍实时渲染
- 软件渲染云环境 300 帧测量平均约 59.9 FPS，95 百分位帧时约 16.7 ms（受项目 60 FPS 上限限制）
- 此短测量不是所有设备或全路线的性能保证

## 当前功能边界

- 岸线碰撞使用小艇中心加八个圆周采样点，不是精确船体多边形
- 靠泊采用低速、朝向与目标范围判定，未接入实体码头碰撞、绳索固定或人物上岸动画
- 静态场景有意先验证轮廓与空间关系；最终植被、建筑、灯光和材质仍需精修
- 自动输入回放不能替代人工手感与触屏测试；本轮另加入合成触屏输入与横竖屏验收，尚无真实触屏硬件验收
